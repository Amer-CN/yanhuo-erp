## 三、问题清单（按「用户能感知的收益」排序）

> 证据均可复现：`scripts/ux-probe-20261112/` 下同名 json + `docs/screenshots/proactive/` 截图。

### P1【H】连点穿透：保存后立刻自动开的选商品弹层，会把后续连点吃成「多记一单 + 多一个商品」
- **现象**：手套/强光下手指连点「保存并记下一单」，第 4 次点击起就落在刚弹出的弹层上：连中 3 次商品卡（加了货）→ 3 次「完成」（关掉弹层）→ 又 3 次「保存」，于是多记了单。实测 5 连点（0.1s 间隔）→ **3 单**：`摔炮 ¥2.00`（本意）+ **`手持烟花棒 ¥5.00`（完全没想加的）** + 原有的 `¥26.50`。
- **证据**：`C1.json` → `five_taps.clicks = ["保存并记下一单"×3, "手持烟花棒"×3, "完成（回单据）"×3, "保存并记下一单"×3]`；`home_after_5taps = "…已记 3 单 / 手持烟花棒 ×1 / 摔炮 ×1 / 26.50"`；截图 `C3-five-taps.png`、`C4-home-after-5taps.png`。双击 2 次（0.12s）只记 1 单，但落点已变成「完成（回单据）」。
- **一句话改法**：保存成功后延迟 400–600ms 再自动开弹层，并在弹层出现后的 400ms 内忽略第一次点击（或给弹层一个 200ms 的「入场锁定」）。
- **成本**：**S**

### P2【H】进货 / 盘亏的数量框把小数点「吞掉」，1.5 变成 15（×10，无提示）
- **现象**：`1.5` 打进去先变 `1` 再变 `15`（每敲一个字符 `replace(/\D/g,'')`），用户以为还是 1.5，实际记账 15。
- **证据**：`B2.json` → `purchase."qty='1.5'".qty = "15"`、`adjust."input='1.5'" = "15"`；对照开单页 `B1.json` → 输入 `3.5` 时框内回退原值并出红字「数量填整数」。
- **一句话改法**：进货数量、盘亏数量复用 `RecordLineCard.normalizeQtyText`（含 `[.,．，]` 即整次拒绝 + 就地提示）。
- **成本**：**S**

### P3【M】保存后的「已记 1 单」Toast 压住自动弹出弹层的标题，连续开单时几乎常驻
- **现象**：弹层顶边 84，Toast 占 72–150；「选商品」标题与「本单已加 N 种」被完全遮住，用户容易以为「页面没反应 / 没开新单」。
- **证据**：`X.json` → `toast_vs_picker = {toast:[16,72,374,150], sheet_top:84, overlap_toast_close:true, z_toast:1100}`；截图 `X1-toast-over-picker.png`（标题只剩半个轮廓）；连续 5 单每单重置 6s。
- **一句话改法**：保存后弹层打开时把 Toast 下移到弹层内容区顶部之外，或连续开单改为在底栏显示「已记 N 单 · 撤销」而不是浮层 Toast。
- **成本**：**M**（与 P1 同一处，建议一起改）

### P4【M】开单页看不到「离线 / 待同步」状态
- **现象**：断网时记账页有横条提示；一进开单页，顶栏（含状态灯）整个隐藏，页面内也没有任何离线标记。断网保存的 Toast 是「已记 1 单 ¥2.00」——没有「待上传」字样。
- **证据**：`E1.json` → `offline_note="离线，照常记账；联网自动补发"` 而 `editor_offline_note=null`；`offline_save.toast="已记 1 单 ¥2.00 | 撤销"`、`dot="同步状态：离线，联网自动补发"`（只能在首页看到）；截图 `E1-offline-home.png`、`E2-offline-saved.png`。
- **一句话改法**：离线时在开单页底栏合计旁挂一个「离线 · 待上传」小徽标；离线保存的 Toast 改成「已记 1 单 ¥2.00 · 待联网上传」。
- **成本**：**S**

### P5【M】结账后无法反悔：撤销入口只活在结果弹层里，且首页立刻归零
- **现象**：`确认收摊结账` → 结果弹层可 `撤销结账`（2 次点击）；一旦点「完成 / 查看本场报表 / 关闭」，记账页变成「还没开张」，全应用再无「撤销结账」入口；刚才那场的 ¥25.00 在记账页也看不到。
- **证据**：`C2.json` → `close_result_buttons=["撤销结账（下一场开始前可用）","完成","查看本场报表"]`；`home_after_close="还没开张 … 本场已记 0 单 ¥0.00"`；`reopen_entry_visible=0`、`home_buttons` 无相关项；全仓 grep「撤销结账」仅 `CloseSessionFlow.tsx`。
- **一句话改法**：没有进行中场次时，记账页保留一张「上一场 14:03 结账 · ¥25.00」卡片，卡内含「撤销结账」和「补记一笔」。
- **成本**：**M**

### P6【M】进货进价填负数能保存，被静默存成 0 成本
- **现象**：进价 `-5` → 折算显示「成本合计 ¥0.00」→ 保存成功 → 批次明细「进价 ¥0.00/挂」，毛利被虚高。
- **证据**：`B2.json` → `cost='-5'.calc="折算：5 箱 · 成本合计 ¥0.00"`、`save_negative_cost.toast="已进货 大地红 1000 响 1 挂"`、批次「进价 ¥0.00/挂」；截图 `B5-purchase-negative-saved.png`。
- **一句话改法**：进货校验 `costFen < 0` 直接报「进价不能是负数」，不要用 `Math.max(0, …)` 静默兜底。
- **成本**：**S**

### P7【M】弹层打开时按安卓系统返回键，直接退出应用
- **现象**：选商品弹层开着时按返回，应用消失（`about:blank`），既没关弹层也没提示。草稿靠 localStorage 保住了（回来仍在），但用户会以为「刚才那单丢了」。
- **证据**：`F.json` → `before_back={url:"http://127.0.0.1:4173/", picker:1}` → `after_back={url:"about:blank", app_gone:true}`；`after_forward={qty:"7", amt:"99"}`；截图 `F5-after-android-back.png`、`F6-after-forward-draft.png`。
- **一句话改法**：弹层/编辑器打开时 `history.pushState` 一层，监听 `popstate` 先关层；没有可关的层才让系统返回生效。
- **成本**：**M**

### P8【M】「添加商品」按钮在屏幕中段（y=502），单手拇指够不到
- **现象**：开单页唯一的「加下一个商品」入口在 502（比下 1/3 起点 562.7 高 60px），戴手套单手要挪动握姿；首单时的空态按钮也在同一位置。
- **证据**：`G.json` → 开单页 `添加商品 cy=502, 下1/3=false`；同页「保存并记下一单」804 ✓ 对比；截图 `F1-editor-filled.png`。
- **一句话改法**：商品行列表底部再放一个「+ 添加商品」的浮条（与合计同行），或把现有按钮贴到列表尾部之后（自然落到底部区域）。
- **成本**：**S**

### P9【L】从「去建商品」建完后回不到刚才的单，多花 3 步
- **现象**：空商品时点「去建商品」→ 新建 → 保存 → 停在商品管理页（toast「商品已建」），只能 返回→记账→记一笔 重新开始；刚建的货也不会自动带进单里。
- **证据**：`H.json` → `H2.steps` 11 步，`after_save_product.page="新建 / 小红鞭 / 炮 / ¥5.00/挂 · 可砍价 / 库存 0 挂"`，可见按钮只有 `返回 / 状态灯 / 新建`；总耗时 10.5s。
- **一句话改法**：记录来源页，从开单页跳去建商品后保存成功自动回开单页并把该商品加入本单。
- **成本**：**M**

### P10【L】「库存总件数」把负库存按 0 计，和列表里的 -15 挂对不上
- **现象**：同一个屏顶卡「库存总件数 0」，下面一行「库存 -15 挂 · 负库存」。结账前扫一眼总件数会误判「没货」，实际是**欠货 15 挂**。
- **证据**：`D.json` → `stock_page="库存总件数 0 … 大地红 1000 响 … 库存 -15 挂 · 负库存"`；源码 `StockPage.tsx:68` `qty += Math.max(0, s)`；截图 `D2-stock-negative.png`。
- **一句话改法**：总件数改「净件数（可为负）」或补一行「欠货 15 挂」。
- **成本**：**S**

## 四、我建议先修的 5 条（含理由）

1. **P1 连点穿透（H）** — 唯一会**直接产生错单**的问题，而且是在最高频操作上；改法是「延迟 500ms 开层 + 400ms 入场锁」，一天就能改完，收益/成本比全表最高。
2. **P2 进货/盘亏 ×10（H）** — 静默改数，摊主事后对不上账也查不出来；已有 `normalizeQtyText` 可复用，属于「把成熟口径搬过去」，风险极低。
3. **P4 开单页离线提示（M）** — 断网是两个摊位的常态，用户对「到底存没存上云」的信任全靠这一处；加一个角标 + 改一句 Toast，成本 S，心理收益最大。
4. **P3 Toast 压住弹层标题（M）** — 和 P1 同一处代码，顺手一起改；不然 P1 延迟开层后，用户更看不出「弹层开了」。
5. **P5 结账后反悔入口（M）** — 收摊是每天一次的不可逆动作，「结完发现漏单」必然发生；现状只能去报表补记，且记账页归零会让人以为数据没了。成本 M，但属于「一次做完长期受益」。

> P6（负进价）建议排第 6：概率低，但改起来 3 行；如果这轮只做 5 条，可以并入 P2 一起提交（同属进货校验）。

## 五、不建议改的（附理由，避免过度设计）

1. **不给「保存并记下一单」加二次确认/长按**：双击实测只记 1 单（`C1.json double_tap` → 1 单），`busy` 已生效；加确认会把 2s/单拖到 4s，摊位场景不可接受。要治的是「弹层提前吃点击」（P1），不是按钮本身。
2. **不做全站防连点/防抖框架**：本轮连点返回、连点状态灯、快切 5 tab、连点删除全部无异常（console 错误 0），现有 `busy`/`restoring`/`deleting` 守卫够用。
3. **不把「清空全部数据」挪到更好找的位置**：危险操作藏深是对的；第 3 步「不清了（保留数据）」已实测安全（C 表最后两行），再加一层确认只会让真需要清空的人多两步。
4. **不把「收摊结账」改到浮条上**：一天一次的动作，占掉最贵的底栏不划算；P8 只提「添加商品」，没提它。
5. **不改「已记 1 单」文案结构**：`e2e-smoke.py` 按这个名字断言；P4 只建议离线时追加「· 待联网上传」，主串不动。
6. **不给数量框开小数**：整件/整箱是现金对账语义，小数数量没有业务意义；该做的是**拒绝并提示**（P2），不是放开。
7. **不改 6 秒撤销寿命**：实测 6.5s 后消失，与注释一致；摊位上手不会 6 秒后才后悔，延长反而会长期压住弹层（P3 的诱因之一）。
8. **不重做「删除后弹层自动关闭」**：实测删除后详情框会关（`C4.json after_delete.sheet_count=0`），列表行同时出现「已删除 + 撤销 + Toast 撤销」，三处入口已经足够。
