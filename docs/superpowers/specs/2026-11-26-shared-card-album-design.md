# 夫妻共享烟花卡册设计

> 状态：待用户确认。确认前只写设计稿，不改产品代码、不安装依赖、不 push、不 deploy、不写真实账本。
>
> 日期：2026-11-26

## 意图

在现有烟花进销存 PWA 中增加一个“夫妻共同收集”的趣味卡册：每个春节赛季里，销售毛利达到里程碑后，商品卡升级、卡册等级提升；赛季结束归档，下个赛季重新收集。卡片支持分类插画、蓝/金/闪品质、手机陀螺仪跟随、详情页 360° 拖动与释放惯性。

重点不是做一套卡牌游戏，而是复用现有账本和设计系统，增加一个有情绪反馈的小功能。

## 已确认的产品决定

1. 进度来源：**摊位销售**，不是进货。
2. 进度标尺：**毛利金额**，不是销量或营业额。
3. 两层进度：
   - 本赛季共享总毛利 → 卡册等级。
   - 本赛季单商品毛利 → 该商品卡的品质。
4. 成本待补的销售先不计入卡册；只统计 FIFO 成本完整的有效订单。
5. 卡片跟随当前有效毛利升降级，不保留已经降级的状态。
6. 第一版卡面使用**分类插画 + 商品名**，不做商品图片上传。
7. 动效方向：**Motion + CSS 3D + 陀螺仪**。
8. 直接集成进现有 PWA，不做独立 demo 或新服务。
9. 第一版只显示**夫妻共享进度**，不显示个人贡献，避免现有本机操作人编号未同步而造成误归属。
10. 品质与卡册等级阈值第一版使用代码内默认值，不做阈值编辑页，也不新增配置设置项。
11. **按赛季收集**：每年 12 月 25 日（圣诞节）开始，到次年元宵节结束；每个赛季独立从 0 开始，赛季结束后卡册归档保留。
12. 卡册等级按赛季毛利设 5 级基础档（¥0 / ¥2,500 / ¥5,000 / ¥7,500 / ¥10,000），**Lv.5 之后每多 ¥10,000 升一级**，不封顶。
13. 单商品品质阈值：R ¥0、SR ¥50、SSR ¥200、UR ¥500。

## 目标

- 两个人无论在哪台手机打开卡册，都看到同一份共享进度。
- 断网可查看和操作卡册；联网后随现有账本同步自动更新。
- 不同商品按利润贡献推进，避免二踢脚和大礼花因销量量级不同而被固定件数卡住。
- 卡册是一个**春节赛季**，赛季结束后归档；新的赛季重新开始收集。
- 卡册视觉沿用“夜间余烬”玻璃体系，不另起一套卡通游戏 UI。
- 动效有质感，但不阻塞开单、不持续占用大量 GPU、不干扰页面滚动。
- 不新增业务表、同步 kind 或后端接口。

## 非目标

- 不做随机抽卡、开包赌博、交易、对战、多人实时房间。
- 不做账号体系、聊天、排行榜、外部素材市场。
- 第一版不做个人贡献拆分、阈值编辑页或复杂限定卡奖励。
- 不做商品图片上传、3D 模型、WebGL 卡牌。
- 不改变现有销售、库存、FIFO、报表和同步口径。
- 不在本轮 push、deploy、执行生产 SQL 或操作真实账本。

## 方案取舍

### A. Fork 整套开源卡牌游戏

不采用。会带入对战、账号、实时服务、品牌美术和额外后端，与现有本地优先 PWA 不匹配。

### B. 独立卡册服务 + 独立存储

不采用。会出现第二套同步、备份和冲突逻辑，违背“账本只有一个真相”的原则。

### C. 现有账本派生卡册（采用）

卡册状态由现有 `products / batches / orders / lines` 实时计算，不落派生表。共享进度天然跟随现有 Dexie + Supabase 同步，删单、作废、成本修正也会自然反映。

## 数据合同

### 赛季

- 赛季区间：每年 **12 月 25 日 00:00**（本地时间）开始，到次年**元宵节 23:59:59**（本地时间）结束。
- 元宵节 = 农历正月十五 = 当年春节初一 + 14 天；用一张春节日期表计算，不引入农历库。
- 春节日期表（`CHINESE_NEW_YEAR`，只存初一日期，元宵节按 +14 天推出）：

| 年份 | 春节（正月初一） | 该年元宵节 |
|---|---|---|
| 2025 | 01-29 | 02-12 |
| 2026 | 02-17 | 03-03 |
| 2027 | 02-06 | 02-20 |
| 2028 | 01-26 | 02-09 |
| 2029 | 02-13 | 02-27 |
| 2030 | 02-03 | 02-17 |
| 2031 | 01-23 | 02-06 |
| 2032 | 02-11 | 02-25 |
| 2033 | 01-31 | 02-14 |
| 2034 | 02-19 | 03-05 |
| 2035 | 02-08 | 02-22 |
| 2036 | 01-28 | 02-11 |
| 2037 | 02-15 | 03-01 |
| 2038 | 02-04 | 02-18 |
| 2039 | 01-24 | 02-07 |
| 2040 | 02-12 | 02-26 |

- 表内日期应在实现时用权威农历数据再复核一次；2025–2037 已在本设计阶段核对，2038–2040 待复核。表外年份回退到 **3 月 5 日** 作为赛季结束日，并在卡册页标注“结束日待更新”。
- 赛季用开始年份命名：`2026 赛季` = 2026-12-25 → 2027 年元宵节。
- 赛季外（元宵节之后到当年 12 月 25 日之前）的销售**不计入任何赛季**，但卡册页照常展示，不做拦截。
- 卡册页永远给出一份可看可玩的卡册：赛期内显示当季；赛季外显示账本里最近一个赛季（已收官，卡面即最终结果）；一个赛季都没有时显示下赛季预览。页面只在头卡用「进行中 / 已收官 / 即将开始」标状态，不出现整页拦截提示。
- 归属规则：订单按所属场次的 `session.startedAt` 本地日期归属赛季；没有场次的旧数据回退到 `order.createdAt` 本地日期。这样结账后**补记**的单仍算回原来那一场，而不是算进补记当天所在的赛季。
- 往季归档直接从现有订单按赛季区间**实时计算**，不落库；因此删单、作废、补成本会同时修正往季结果。

### 有效销售

- 只统计 `!order.voided` 的订单及其明细。
- 作废订单不计入；撤销作废后重新计入。
- 缺订单头的孤儿明细不计入。
- 当前没有独立的销售退货流水；退货通过作废原订单处理，因此卡册随作废回退。

### 毛利口径

**先对全库做一次 FIFO 重放，再按赛季过滤**，不按赛季单独重放：

```text
fifo = fifoAllocate(全部批次, 全部订单, 全部明细)   // 与报表同一口径
lineGrossFen = line.amountFen - fifo.lineCost[line.id]
```

> 为什么不能先筛赛季再重放：FIFO 是跨时间顺序扣批的。只拿某一季的订单去重放，会把最早的批次算给这一季，毛利虚高。

- 只有 `fifo.lineCost` 存在且 `fifo.uncoveredQtyByLine[line.id]` 为 0 的明细才计入。
- 缺批次成本、超卖导致的估算成本不计入，界面显示“成本待补，暂不计入”。
- 赠品与报表同口径：销售额为 0、成本照计，因此会冲减毛利。
- 负毛利会冲减累计进度；累计值小于 0 时展示 0，不产生负等级。
- 折扣已经反映在 `amountFen` 中，不重复扣减。

### 单商品卡（按当前赛季）

```text
productGrossFen = Σ 本赛季该商品成本完整的有效明细 lineGrossFen
rarity = 按 productGrossFen 落在商品品质阈值中的最高档
```

品质只看**本赛季**该商品毛利；新赛季所有卡回到基础品质重新收集。

| 品质 | 视觉 | 本赛季单商品毛利阈值 |
|---|---|---:|
| R | 灰白银边 | ¥0 |
| SR | 青蓝蓝边 | ¥50 |
| SSR | 金色金边 | ¥200 |
| UR | 彩虹闪膜 | ¥500 |

阈值为代码内具名常量，第一版不提供编辑入口。

### 共享卡册（按当前赛季）

```text
albumGrossFen = Σ 本赛季所有成本完整的有效明细 lineGrossFen
albumLevel = 按 albumGrossFen 落到下面的档位
```

| 卡册等级 | 本赛季共享毛利门槛 |
|---|---:|
| Lv.1 | ¥0 |
| Lv.2 | ¥2,500 |
| Lv.3 | ¥5,000 |
| Lv.4 | ¥7,500 |
| Lv.5 | ¥10,000 |
| Lv.6 起 | **每多 ¥10,000 升一级**，不封顶 |

换算公式：

```text
albumLevel = p < 2500  ? 1
           : p < 5000  ? 2
           : p < 7500  ? 3
           : p < 10000 ? 4
           : 5 + floor((p - 10000) / 10000)

下一级门槛 = 1~4 级取 2500 / 5000 / 7500 / 10000；
            5 级及以上 = 10000 × (当前等级 - 3)
```

Lv.2–Lv.5 用头卡边框档位区分（微光 / 银边 / 金边 / 赤金）；Lv.6 起只增加等级数字，复用第 5 档边框，不追加新美术，避免无限出图。

### 个人贡献

第一版不展示个人贡献。现有 `operatorSelf` 是本机设置且不参与同步，`operatorA / operatorB` 只保留兼容旧数据；在缺少可靠的双人身份映射前，不按操作人拆分毛利，避免两台手机显示不同归属。后续若要做个人贡献，再单独设计同步身份映射。

## 界面与交互

### 入口

- “更多”页新增“我们的卡册”入口，副标题固定写“按春节赛季收集商品卡”；等级、进度和赛季状态都放在卡册页里显示，入口不重复计算。
- 新增懒加载子页面 `album`，不占底部主导航。
- 无商品、无有效销售、成本待补都有明确空状态。

### 赛季与归档

- 卡册页顶部固定显示：赛季名、起止日期、本赛季共享毛利、当前等级、下一级还差多少。
- 头卡右上角标当前状态「进行中 / 已收官 / 即将开始」；只有进行中才显示进度条与「再赚多少升级」。
- 任何状态下都渲染分类/品质筛选和卡片网格，卡片详情始终可打开。
- 往季归档从现有订单实时计算，按赛季倒序列出最近 10 季；每季显示最终等级和毛利。
- 赛季结束不弹窗、不强制结算；赛季只是按日期自动切换的视图。

### 卡册网格

- 显示全部未停用商品；已停用商品保留在卡册尾部并标“已停售”。
- 每张卡显示：分类插画、商品名、本赛季品质、本赛季毛利、下一档差额。
- 本赛季没有正毛利的商品显示灰色未点亮卡，不隐藏。
- 支持分类筛选和 R/SR/SSR/UR 筛选。
- 网格卡在 hover 设备上做轻量倾斜；触屏不倾斜，避免与纵向滚动抢手势。

### 卡片详情

- 大尺寸双面 3D 卡：正面为商品卡，背面为卡册标识和品质说明。
- 显示本赛季商品毛利、当前品质、下一档差额。
- 手指横向拖动可连续 360° 旋转；松手后按拖动速度惯性减速停下。
- 陀螺仪开启时，手机倾斜会让卡片轻微跟随；手指拖动期间暂停陀螺仪，避免抢方向。
- iOS 通过显式“开启体感倾斜”按钮请求权限；拒绝或不支持时静默降级为触摸/鼠标。
- 仅当卡册已打开、组件已挂载且品质从旧值变为更高值时，播放一次翻面/流光；首次打开和后台同步期间不补播。降级只显示简短中性提示，不做惩罚动画。

### 动效实现边界

- `motion/react` 负责旋转值、弹簧、速度和释放惯性。
- CSS 负责正反面、透视、品质边框、glare、彩虹闪膜和流光。
- 陀螺仪使用 `deviceorientation`，以首次读数作为中性姿态，做低通平滑；避免在手机竖直握持时直接使用原始 `beta/gamma` 造成万向节死锁。
- `prefers-reduced-motion` 开启时关闭持续流光、自动旋转和惯性，保留瞬时状态切换。
- 同一时间只允许一张详情卡运行复杂 3D；网格卡保持静态或轻量 CSS 效果。

## 视觉

- 沿用现有 GlassKit、`src/tokens.css` 和“夜间余烬”品牌，不引入宝可梦或其他品牌美术。
- 分类插画使用本地 SVG：炮、烟花、儿童、组合各一套；随 PWA 预缓存，断网可用。
- 品质颜色只用于边框、徽章和材质，不改变正文对比度。
- 卡片正反面遵循 `transform-style: preserve-3d`；避免在 3D 父层使用会压平层叠的 `overflow / filter / mask / mix-blend-mode`。

## 性能与离线

- 卡册页面懒加载，Motion 随卡册页一起懒加载，不进入首屏包。
- 插画为本地矢量资源，不请求外部图片。
- 卡册计算复用现有全量数据快照，避免每个卡片重复扫订单/明细。
- 只对详情页当前卡注册陀螺仪监听；离开页面立即移除。
- 断网时使用本机账本计算；联网同步后自然更新。

## 对现有系统的影响

- `src/db/`：新增纯函数卡册计算模块（赛季归属、复用 `fifoAllocate`、等级换算）+ 春节日期表；阈值用具名常量。
- `src/ui/`：新增卡册页、卡片组件、详情 Sheet 和陀螺仪 hook；`MorePage` 增加入口。
- `src/styles.css` / `tokens.css`：新增卡册组件令牌和 3D/品质样式。
- `package.json`：新增 `motion` 依赖。
- 不升 Dexie schema，不改 Supabase 表或 RLS，不新增同步设置项。
- 卡册与赛季归档都没有独立持久化状态，因此无需修改备份格式。

## 风险与处理

| 风险 | 处理 |
|---|---|
| 补录或修正进货成本会改变历史毛利，导致卡片升级/降级 | 明确告知“卡册跟随当前有效毛利”；详情页显示最近更新时间 |
| 缺成本销售被误计 | 复用 `uncoveredQtyByLine`，整条缺成本明细排除并显示“成本待补” |
| 赠品或亏损销售让进度下降 | 与报表毛利同口径，允许负毛利冲减；累计展示不小于 0 |
| 两台手机对“当前进度”理解不同 | 入口明确显示“当前等级到下一等级”；详情同时显示毛利金额和下一档差额 |
| 陀螺仪与拖动打架 | 拖动时暂停传感器，松开后恢复 |
| 低端手机 GPU 压力 | 网格默认不做持续动画；只有 UR 卡保留一条低频流光（数量少），Motion/3D 只在当前详情卡运行 |
| 卡片等级看起来“不公平” | 用毛利而非件数；阈值集中在具名常量便于后续调整，界面始终显示金额和下一档差额 |
| 春节日期表覆盖不到当年 | 表外年份用保守结束日（3 月 5 日）并在卡册页标注“结束日待更新”；升级只需补表，不改逻辑 |
| 补记被算到新赛季 | 按场次 `startedAt` 归属，不按补记时间 |
| 跨赛季的长场次 | 整场归开场日所在赛季；极端情况可在赛季切换时收摊重开一场 |
| 赛季外打开卡册以为没内容 | 赛季外显示最近收官赛季，卡片与筛选照常可用；只有状态角标不同 |

## 验收

### 计算单测

- 作废/恢复订单会减少/恢复共享与单品毛利。
- 成本完整明细计入；缺批次成本明细排除。
- 赠品和负毛利按报表口径冲减。
- 单商品品质边界：¥49.99 → R，¥50 → SR，¥200 → SSR，¥500 → UR。
- 卡册等级边界：¥2,499 → Lv.1，¥2,500 → Lv.2，¥9,999 → Lv.4，¥10,000 → Lv.5，¥19,999 → Lv.5，¥20,000 → Lv.6，¥30,000 → Lv.7。
- 赛季边界：12-24 23:59 归上一季；12-25 00:00 归新季；元宵节当天计入，次日不计入。
- 补记到上赛季场次的订单归上赛季；无场次旧数据按订单时间归属。
- 赛季外订单不计入任何赛季。
- 赛季外打开卡册仍返回最近一个赛季（archived）；一个赛季都没有时返回下赛季预览（upcoming）。
- 卡册页头卡百分比按“当前等级到下一等级”计算；Lv.5 之后以 ¥20,000 为下一档。
- 往季归档按赛季区间计算，且与当季用同一套 FIFO 结果。
- 首次打开不播放升级动画；已挂载期间品质升高只播放一次。
- 已停用商品仍保留卡册条目。
- 相同账本在两次计算中结果稳定，不依赖设备。

### 交互与同步

- A 手机开单后，B 手机联网同步看到同一卡册进度。
- 断网开单先更新本机卡册，联网后合并。
- 作废订单后两台手机最终都回退对应进度。
- 陀螺仪授权、拒绝、不支持、离开页面清理均正确。
- 360° 拖动松手减速； reduced-motion 下不惯性。
- 网格纵向滚动不被卡片拖动劫持。

### 项目门禁

- 现有 Vitest、TypeScript、lint、build 通过。
- 卡册计算和组件有新增测试。
- 不访问真实账本，不 push、不 deploy；目标手机真机体验由用户人工执行。

## 规模判断

这是中等规模功能：赛季与毛利计算、边界测试较小，主要工作在卡册 UI、详情 3D 交互和手机传感器适配。第一版不包含图片上传、限定卡美术、阈值编辑和复杂奖励系统。
