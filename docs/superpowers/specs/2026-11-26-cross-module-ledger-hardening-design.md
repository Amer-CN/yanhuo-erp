# 跨模块账本加固设计

## 意图

修复第一批审计合同修复暴露出的组合风险：手动合并与同步待决状态互相污染、已结账快照失真、恢复后陈旧撤销、破坏性合并缺乏持久恢复点，以及真实 E2E 清理未知结果无法跨进程重试。

## 目标

- 手动合并使用同一份纯计划完成预览与提交；同 ID 订单分歧默认保留本机，只有用户明确选择“采用备份”才替换整单。
- 合并事务同时清理受影响订单的待决明细、冲突和远端撤销快照，并重算受影响已结账场次汇总。
- 普通同步暂停不使本地业务写失效；只有维护/恢复/清空/重连确认造成的数据换代使旧命令失效。
- 恢复前生成的“对方改动”撤销意图在数据换代后必须拒绝，不能污染新账本。
- 同代际撤销还必须匹配远端应用后的当前记录指纹；冲突采用同时匹配 local 快照、订单组结构和当时 outbox revision。
- 合并前总是持久保存快照；`lastImportAt` 与撤销指针和业务变更同事务提交，不再出现“已合并却报失败”。
- pre-merge 快照在备份库事务内原子创建并携带 24 小时跨标签页预留；活跃预留必保留，失败显式放弃，崩溃遗留过期回收；主库关闭时保守保留所有 pending。
- 真实 E2E 的 ledger 与 operationId 持久化到无密钥的运行文件；网络未知结果同号重试，清理失败不掩盖原始测试异常。
- 报表单场/批量共享累加逻辑；备份显式标记完整订单 manifest 能力；文档与现役行为一致。

## 非目标

- 不重写同步状态机、不引入服务端逻辑时钟、不执行生产 SQL。
- 不访问真实账本、不 push、不 deploy、不操作目标手机。
- 不把旧备份缺 manifest 的数据猜成完整订单组。
- 不清理既有测试账本元数据；只补保留/重试说明。

## 关键合同

### 合并计划与用户选择

- `planOrderMerge(existingOrders, existingLines, incomingOrders, incomingLines, choices)` 是纯函数，返回写入/删除计划、计数和可供 UI 展示的订单变化。
- 同 ID 且内容相同：保留本机。
- 同 ID 且内容不同：默认保留本机并计为冲突；完整备份组可由用户显式选择 `incoming` 后整组替换。缺 manifest 的来件不允许选择替换。
- 新完整订单遇到本机同 orderId 孤儿明细：默认冲突保留现场；用户显式选择 `incoming` 后才删除孤儿行并入队墓碑。
- 空 manifest、重复 ID、缺/多明细、负数量/金额、非法商品引用、非法时间均在写入前拒绝。

### 合并事务一致性

- 事务范围包含 `conflicts`、`remotePendingLines`、`remoteOrderUndo`。
- 所有本次涉及的订单 ID 清除待决明细和远端撤销快照；实际变更记录清除对应冲突。
- 业务写入、墓碑、冲突清理、汇总重算、outbox、`lastImportAt` 与持久撤销指针同事务提交。
- 已结账场次汇总从最终订单/明细/批次重算；首页与报表使用同一结果。

### 数据换代

- `SyncControlRow.generation` 继续服务租约/暂停 CAS；新增 `dataGeneration` 服务数据换代。
- `pause/resume` 只改 `generation`；`runMaintenance` 同时递增两者。
- repo 业务写校验 `dataGeneration`；错误文案改为“账本已更新，请刷新后重试”。
- 启动示例数据写入同样在事务内外检查 maintenance，不能在恢复窗口污染新账本。
- `RemoteChange` 与冲突行记录产生时的 `dataGeneration`；撤销/采用远端/删除记录在提交事务内校验原代际。

### E2E 清理

- 运行文件只保存项目 URL、base ledger、run ledger、operationId、创建时间，不保存 key；URL 不匹配时拒绝复用。
- 真实模式全程持有操作系统文件锁，第二个并发进程拒绝启动；首次创建使用 `O_EXCL`，删除前重新比对身份。
- 每轮开始先解决上一份未确认清理；成功后删除运行文件并创建新运行。
- 网络错误、超时、5xx 使用同一 operationId 重试；回执非法立即失败。
- JWT 形态 key 补 `Authorization: Bearer`，与客户端合同一致。
- 原始测试异常优先保留；清理异常作为附加失败信息，不替换根因。

## 验收

- fake-indexeddb 覆盖待决明细不被合并后同步重新注入、冲突/撤销快照清理、汇总一致、陈旧撤销拒绝、普通暂停不拒绝本地写。
- 合并测试覆盖用户选择、默认保留、损坏备份原子拒绝、持久快照与元数据同事务。
- Python 单测覆盖运行文件复用、同号重试、鉴权头、失败保留与无 Playwright 依赖。
- 全量 Vitest、Python、tsc、lint、build、diff check 通过；最终做独立审查（路由不可用则明确记录自审限制）。
