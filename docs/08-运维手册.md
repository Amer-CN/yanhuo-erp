# 运维手册（烟花进销存）

> 适用：`https://amer-cn.github.io/yanhuo-erp/` 的两台设备（摊主 + 家里）。
> 原则：**先保数据，再修同步**；任何清空/恢复动作前，先导出一份备份。
> ⚠️ 不要把 `vite dev` / `preview` 暴露到公网或不可信局域网；launch-editor 相关漏洞可在 dev 进程被利用。默认只监听 `127.0.0.1`，真机联调临时 `pnpm dev --host`，用完即关。
> 相关文档：[云同步设置](03-云同步设置.md)、[使用说明](02-使用说明.md)、[技术债登记表](05-技术债登记表.md)。

## 1. 同步一直失败（401 / 403 / 超时）

**症状**
- 设置页「云同步」状态显示「同步出错」；顶部/设置里能看到 `Supabase 401`、`403`、`Failed to fetch` 或 `timeout`。
- 两台手机都开单，但互相看不到新单。

**判断**
- 401/403：同步码不对、RLS 策略没建好，或 key 抄错/抄漏。
- 超时 / `Failed to fetch`：手机网络、DNS、Supabase 项目暂停，或公司/酒店 Wi-Fi 拦截。
- 只有一台失败：先看失败那台的「修改配置」里三项是否和另一台完全一致。

**处置**
1. 先点「测试连接」：
   - 显示「连接成功，云端表可访问」→ 是同步链路问题，继续第 2 步。
   - 仍报 401/403 → 对照另一台手机，重新填 Project URL、anon key、同步码，保存并启用。
2. 切换网络（4G/5G 与 Wi-Fi 互换），再点「立即同步」。
3. 确认 Supabase 控制台项目没有暂停（见第 6 节）。
4. 确认 `supabase/schema.sql` 里的 `yh ledger access` 策略存在（人工在 SQL Editor 检查，Agent 不执行）。
5. 在浏览器控制台（可选，仅维护者）执行下面命令看配置是否存在：

```powershell
# 在应用页面按 F12 → Console；只读，不打印完整 key
Get-Content -Path $env:TEMP\yh-sync-check.txt -ErrorAction SilentlyContinue
# 或直接看：localStorage.getItem('yh-sync-url') / 'yh-sync-ledger' 是否为空
```

**验证**
- 「云同步」状态变「已连接」，「待推送 0 条」。
- 一台记一笔，另一台 10–20 秒内能在「销售记录」看到。

## 2. 离线开单后不补发

**症状**
- 摊位断网时记了单，回店联网后另一台手机仍看不到；设置页「待推送」一直大于 0。

**判断**
- 看「云同步」状态与「上次同步」时间：
  - 状态「离线」→ 手机还没真正联网；
  - 状态「已连接」但「待推送」不动 → push 被 400/401 拦截；
  - 状态「未开启」→ 同步被关闭（例如恢复备份后会自动暂停）。
- 若两台手机都显示「未开启」，是关闭了同步，不是离线补发失败。

**处置**
1. 确认手机能打开 <https://amer-cn.github.io/yanhuo-erp/>（不是缓存页）。
2. 设置 → 云同步 → 点「立即同步」；仍失败则按第 1 节处理。
3. 若状态「未开启」：点「修改配置」，填好三项，点「保存并启用」。
4. 不要清空数据、不要重装 PWA；本地账本在 IndexedDB 里，清空会丢。

**验证**
- 「待推送」变 0，「上次同步」时间更新；另一台「销售记录」出现补发的单。

## 3. 误删单（进行中场次 / 已结账场次）

**症状**
- 刚记的单不见了；或某单显示「已作废」；或已结账场次里的一单被删。

**判断**
- **进行中场次**：v2 没有独立「删除」按钮；唯一删除路径是保存后 Toast 上的「撤销」。点过「撤销」= 本地单和明细已删，并会同步删除。
- **已结账场次**：不能删除，只能「整单作废」；作废会保留记录、报表不计。
- 判断是「作废」还是「删除」：销售记录里还能看到（带「已作废」）就是作废；完全看不到就是删除。

**处置**
1. 作废：销售记录 → 点开该单 → 「撤销作废」。
2. 进行中场次被删除：
   - 如果另一台手机还没同步到删除墓碑，先在那台导出备份；
   - 在本机「设置 → 本地备份」找删除前的快照（收摊快照/手动快照），点「恢复」（会暂停云同步）；
   - 没有快照就重新记一笔，并在备注写「补录」。
3. 已结账场次被撤销补记：重新「补记到这一场」。

**验证**
- 销售记录/报表金额恢复；设置页「待推送」最终归 0；另一台手机看到一致结果。

## 4. 误清数据

**症状**
- 点过「设置 → 危险操作 → 清空全部数据」，商品/进货/销售都没了；或同时清空了云端。

**判断**
- 清空会清掉本机 6 张业务表（商品、批次、订单、明细、调整、场次）并清空发件箱；**不会**自动备份。
- 若弹窗里选了「同时清空云端账本」，另一台手机也会被清空；否则云端还在，可重新拉回。

**处置**
1. **立即停止**在两台手机上继续记账/清空。
2. 本机恢复：设置 → 本地备份 → 选清空前的快照 →「恢复并暂停云同步」。
3. 没有本地快照：找最近一次「导出备份」的 JSON（微信收藏/文件），用「导入并合并」恢复。
4. 云端未清空时：恢复后先不要开同步，核对金额；确认后再到云同步「修改配置 → 保存并启用」，把本地补回云端。
5. 云端已清空且无任何备份：数据无法从云端找回，只能重录；这是文档里反复强调「每天收摊导出」的原因。

**验证**
- 恢复后报表金额与清空前一致；另一台手机核对同一场次的单数和销售额。

## 5. 换手机 / 重装 PWA

**症状**
- 新手机、重装浏览器、或清理了 Safari 缓存。

**判断**
- 旧手机还能打开 → 用旧手机导出；
- 旧手机已丢/已清 → 只能靠之前的导出备份或云端（若同步一直开启且云端未被清）。

**处置**
1. 旧手机：设置 → 备份与合并 →「导出备份（发微信）」，发到自己的微信收藏。
2. 新手机：打开应用 → 更多 → 设置与同步 →「导入并合并」选 JSON。
3. 填同步码（两台一致）→ 保存并启用；设置本机设备名（两台别重名）。
4. 旧手机如继续使用，建议关闭云同步或改成只读习惯，避免两台同时改同一单。

**验证**
- 新手机报表/销售记录金额与旧手机一致；记一笔后另一台能看到。

## 6. Supabase 配额满或项目暂停

**症状**
- 所有设备同步失败，错误类似 402/429/503，或 Supabase 控制台提示项目 paused / 超出免费额度。

**判断**
- 登录 <https://supabase.com> → 对应项目：
  - 显示 `Paused` → 免费项目长期不访问会暂停；
  - Usage 里数据库/带宽/API 请求接近上限 → 配额问题。
- 账本数据仍在云端；暂停期间本地照常开单，只是不同步。

**处置**
1. 控制台点「Restore project」恢复（可能需几分钟）。
2. 配额问题：升级套餐，或临时关闭云同步、改用「导出/导入合并」（设置 → 备份与合并）。
3. 恢复后各设备点「立即同步」；先确认没有重复单。

**验证**
- 设置页状态「已连接」，待推送归 0；两台设备数据一致。

## 7. GitHub Pages 部署失败

**症状**
- push 到 `main` 后，GitHub Actions 的 `Deploy to GitHub Pages` 变红；线上还是旧版本。
- push 被拒：`refusing to allow an OAuth App to create or update workflow .github/workflows/*.yml without workflow scope`。
- `gh auth refresh` 设备码超时 / `EOF`；或 `git push` 报 `schannel: failed to receive handshake`。

**判断**
- 打开 <https://github.com/Amer-CN/yanhuo-erp/actions> 看失败步骤：
  - `Install` 失败：lockfile 与 package.json 不一致；
  - `Lint`/`Unit tests + coverage` 失败：代码门禁；
  - `Build` 失败：TypeScript/Vite；
  - `deploy` 失败：Pages 权限/环境设置。
- 部署失败不会影响线上旧版本，也不会影响本机已缓存的 PWA。

**处置**
1. 本地复跑同一命令定位：

```powershell
cd F:\AIXM\烟花爆竹
pnpm install --frozen-lockfile
pnpm lint
pnpm test:cov
pnpm build
```

2. 修复后重新提交并 push；或对失败的 workflow 点「Re-run all jobs」。
3. 确认仓库 Settings → Pages → Source 仍是 `GitHub Actions`。
4. 若 push 被 workflow scope 拒绝：
   ```powershell
   gh auth status                 # 看 scopes 是否有 workflow
   gh auth refresh -s workflow    # 设备码授权；失败时先清代理
   ```
5. 若设备码超时 / schannel 握手失败：临时清代理后重试
   ```powershell
   $env:HTTP_PROXY=''; $env:HTTPS_PROXY=''
   git -c http.proxy= -c https.proxy= push origin main
   ```
   成功后再恢复代理设置；不要把代理写进仓库配置。

**验证**
- Actions 最新一次运行全绿；打开线上地址，版本号/新功能已更新（PWA 会提示「有新版本」）。

## 8. 回滚到上一版本

**症状**
- 新版本上线后出现严重问题，需要回到上一个可用版本。

**判断**
- 代码回滚用 `git revert`（不要 `git reset --hard` 改写历史）。
- 只回滚前端不会回滚本地/云端账本；数据库结构变更（如新增列）向后兼容，可保留。

**处置**
1. 找到上一个可用提交：

```powershell
cd F:\AIXM\烟花爆竹
git log --oneline -10
```

2. 回滚有问题的提交（一次一个，解决冲突后再继续）：

```powershell
git revert <坏提交的短哈希>
pnpm build
pnpm test
git push origin main
```

3. 紧急时也可在 GitHub Actions 里对上一次成功的部署运行「Re-run all jobs」。
4. 回滚后两台手机都会收到「有新版本」提示；收摊后再点「更新」。
5. 如果坏版本已经改坏本地数据：先导出当前数据，再按第 10 节恢复备份。

**验证**
- 线上地址恢复正常；两台设备开单/报表可用；Actions 部署绿。

## 9. 轮换 ledgerKey（两台设备同时在场）

**症状**
- 怀疑同步码泄露，或需要把账本换到新密钥。

**判断**
- 轮换会让另一台设备**立即失联**；旧云端数据留在旧同步码下，不会自动迁移。
- 必须两台设备同时在场，并且先各导出一份备份。

**处置**
1. 两台手机：设置 → 备份与合并 → 导出备份（各自一份）。
2. 在其中一台：设置 → 云同步 → 修改配置 → 点「生成」得到新同步码 → 复制。
3. 另一台：修改配置 → 粘贴**同一个**新同步码；两台都点「保存并启用」。
4. 需要旧账本数据：用备份「导入并合并」到新账本，核对金额。
5. 确认新账本正常后，旧同步码对应的云端数据可择日清理（人工操作，先备份）。

**验证**
- 两台状态「已连接」；一台记一笔，另一台能看到；旧同步码不再被使用。

## 10. 从本地备份恢复（恢复后同步暂停）

**症状**
- 记错/误删/误清后，想回到某个时间点的本机数据。

**判断**
- 「本地备份」由收摊自动快照 + 手动「立即备份」组成，保留最近 3 个不同日期 + 最近 1 份迁移前快照。
- 恢复是**整库替换**；恢复后自动写 `yh-sync-disabled=1`，不会自动把旧数据推上云端。

**处置**
1. 设置 → 本地备份，核对时间、单数、销售额，选中要恢复的一份。
2. 点「恢复」→ 二次确认「恢复并暂停云同步」。
3. 恢复后先核对：首页本场金额、报表、销售记录。
4. 确认无误后再开启同步：设置 → 云同步 → 修改配置 → 填三项 → 保存并启用。
   - 三项可从另一台仍正常的设备「修改配置」里抄；两台都暂停时按 [docs/03](03-云同步设置.md) 重新填自己的项目与同步码。
5. 开启同步后先观察「待推送」，避免旧快照覆盖另一台较新的数据。

**验证**
- 恢复后的单数/销售额与快照显示一致；开同步后两台数据一致，且没有重复单。

## 11. 给摊主的三步恢复卡

1. **先别清数据、别重装**：打开「更多 → 设置与同步」，看「云同步」状态。
2. **不能同步**：先换网络 → 点「立即同步」；还不行就拍照记录错误，等维护者。
3. **数据错了/丢了**：打开「更多 → 设置与同步 → 本地备份」，选最近一份点「恢复」，确认后再用。
