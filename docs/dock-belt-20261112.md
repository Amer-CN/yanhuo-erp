# 底栏改造：浮动胶囊 → 网格第 4 行（2026-11-12）

底栏（`.glass-tab-bar-dock` 里的玻璃胶囊 `.glass-tab-bar--floating`）从 `position: fixed`
的视口浮层，改成 `.app-shell` 网格的第 4 行。内容滚动视口的下沿因此等于底栏带的上沿，
「内容从胶囊底下穿过」在结构上不再可能发生。

口径：390×844（iPhone 14 档）、`device_scale_factor=2`、`localStorage['yh-sync-disabled']='1'`、
种子数据 6 单 + 12 条进货。相交面积 = 胶囊 rect ∩ 滚动容器 padding box ∩ 可见元素 rect，
共 7 页 × 5 个滚动位置 = 35 个采样点，每个采样点另做 21 点 `elementFromPoint` 命中测试
（7 列 × 3 行，胶囊上的点最顶层必须是胶囊本身）。

## 一、问题

改造前底栏是 `fixed` 浮层（GlassKit 默认 `left:50%; bottom: calc(16px + safe-area);
transform: translateX(-50%); z-index: 900`），内容区只能靠 `.app-main` 的
`padding-bottom: 172px`（记账页）/ 96px 兜底——**这笔留白只保证「滚到底」那一帧不被盖，
滚动中间的内容照样从胶囊底下穿过**。

审计里的原始观测（`docs/report-page-audit-20261112.md` §11.3，采集时的数据量与页面高度与本次种子不同，
处数/面积不可逐项对齐，这里只借它说明问题真实存在）：

- 报表页首屏 3 处相交 / 522.6px²；
- 滚动到 50% 4 处 / 1623.2px²；
- 滚动到 75% 4 处 / 10798px²。

本次用同一套可复现脚本重扫 7 页 × 5 位置，改前基线：

- **6 个采样点有相交**（共 35 个）：记账页 0%、25%；报表页 0%、25%、50%、75%；
- 单块最大相交面积 **18065.7px²**（记账 0%）与 **18070px²**（报表 0–75%）；
- 相交面积合计 387360.9px²，最差位置报表 50% 有 21 个可见块压在胶囊下面。

根因不是「留白不够大」，而是**浮层与滚动容器不在同一个布局流里**：只要底栏相对视口定位，
任何滚动位置都可能出现相交，padding 只能在终点那一帧碰巧对上。

## 二、方案

1. `.app-shell` 改成 4 行网格：`grid-template-rows: auto auto minmax(0, 1fr) auto`
   （顶栏 / 更新条 / 内容 / 底栏）。第 3 行把 `min-height: 0` 写进轨道定义，内容区是唯一滚动容器；
   第 4 行由底栏真实占位，高度 `89px`。
2. `.glass-tab-bar-dock` 只换定位、不碰外观：`grid-row: 4; position: static; left/bottom: auto;
   transform: none; z-index: auto`，`display:flex; justify-content:center;
   padding: 8px 16px calc(16px + safe-area)`。胶囊本体（`border-radius: 9999px`、渐变背板、
   `backdrop-filter: blur(24px)`、双层投影）仍由 `.glass-tab-bar--floating` 画。
3. `.app-main` 的 `padding-bottom` 从 `172px`（异常补偿）收敛到 `var(--yh-page-gap)` = 14px。
4. 记账页结算浮条 `.checkout-dock`：`fixed` → `.app-main` 内的 `position: sticky; bottom: 0`，
   并成为 `.page-stack` 的流内末元素（`margin-top: auto` 保证内容不足一屏时仍贴底）。
5. 进货页保存栏 `.record-actions--above-dock`：`fixed` → `sticky`，且 `order: 1` 排到视觉流最后，
   否则 sticky 会停在流内原位（实测会漂到屏幕中间、离底栏带 103.2px）。
6. `.app-main--dock`、`.checkout-dock` 都去掉 `safe-area` 的重复计算——**safe-area 只在底栏那一层记一次**。

**为什么不选「在右侧加安全带 / 加大 padding」**：内容是全宽的（列表卡、报表表格都是
`100%` 宽），任何 `fixed` 浮层都会在滚动过程中穿过内容；预留右侧安全带只是把「穿过」换成
「永久少一列可用宽度」，既没消掉相交，又压缩了 390px 屏幕的表格。真实占位才是恒 0 的解。

## 七、已知例外（如实记录，未美化）

1. **`.record-actions`（记账页开单编辑态）仍是 `position: fixed; bottom: 0; z-index: 900`。**
   实测 rect 390×109.7 @ (0,734.3)–(390,844)，`parentCls = record-page`，滚动的是 document。
   但同一视图的 shell 为 `.app-shell--editor`，`shellRows = "auto auto minmax(0, 1fr) auto"`，
   `tabBarItems = 0`、`hasBar = false`、第 4 行高度 0 —— **底栏根本没渲染**，所以「覆盖底栏」
   在当前 DOM 下不会同屏发生（`vsBar = null`，无相交对象）。改造前也是同一分支，非本轮回归。
   但这是**潜在耦合**：一旦以后让编辑态也渲染底栏，这条 fixed 栏就会把它整块盖住。
   要支持「编辑中切 tab」，需另开改动：底栏条件隐藏，或把操作栏改成相对定位/网格行。
2. **任何全屏 Sheet（`glass-sheet-overlay` 390×844，`z-index: 1000`）都会覆盖底栏。**
   实测打开「今天录入」Sheet：`coversBar = true`，底栏无 `z-index`（auto），弹层在上；
   弹层内 `.record-actions` 计数 0。属正常层级，不是缺陷。
3. **iOS 键盘场景未真机验证。** 判断依据：`100dvh` 与 `fixed` 在 iOS Safari 上都相对
   **layout viewport**，软键盘只缩小 visual viewport，不改变 grid 第 4 行高度；因此底栏仍贴在
   layout viewport 底部 → 被键盘**遮住**，不会浮到键盘上方，也不会把内容挤走。改前 fixed 底栏
   同样在键盘下层，行为一致。风险：若后续加 `interactive-widget=resizes-content`（Android 支持、
   iOS 不支持），聚焦时整页会重排；`src/ui/record.css` 的 `app-shell--editor` 注释已明确禁止锁高重排，
   故本轮不加。**需要一台真机才能把「未验证」改成「已验证」。**

## 八、第二批（同日）：动作条也进网格 —— 第 4 行给动作行，底栏顺延第 5 行

第一批只解决了底栏，**两个吸底动作条仍然是浮层**（`sticky; bottom:0`），
本质与改造前的底栏同源：padding 只护住「滚到底」那一帧。

改前实测（390×844，与本文同一套口径）：

| 动作条 | 位置 | 相交 |
| --- | --- | --- |
| 进货页 `.record-actions--above-dock` | 0% | 1 处 / 11269.1px²（盖住「今天已录 N 条」卡） |
| 同上 | 25% | 6 处 / 8649.8px² |
| 记账页 `.checkout-dock` | 0% / 25% / 50% | 7846.4 / 8102.4 / 7844.1px²（盖住页脚说明） |

**改法**：`.app-shell` 改成 5 行 `auto auto minmax(0, 1fr) auto auto`
（nav / updatebar / main / actionbar / tabbar）。页面通过 `createPortal`
把动作条渲染进 `<div className="app-actionbar">`（`src/ui/actionSlot.tsx`
的 `useActionSlot()` + `<ActionBar>`），槽为空时（单测 / Shell 之外）原地渲染。
动作条本身的定位与背景全部去掉，只留普通块；编辑态（`.app-shell--editor`，
文档滚动、不渲染底栏）保留 `fixed` 原样，用 `.app-shell--editor .record-actions` 作用域隔离。

改后实测（`python scripts/action-row-20261112/measure.py`）：

- 相交：7 页 × 5 位置 = 35 点，「内容 vs 底栏带」与「内容 vs 动作行」**全 0**；
  另加 21 点 `elementFromPoint` 命中测试，异常 0。
- 五行轨道：记账 `64 / 0 / 595 / 96 / 89`（px），进货 `64 / 0 / 613 / 78 / 89`。
- 动作行 rect：记账 390×96 @ y=659；进货 390×78 @ y=677。底栏带 755–844 未移动，
  胶囊仍是 **278×65 @ (56,763)–(334,828)**（动作行的高度从内容区那 1fr 里扣，底栏不位移）。
- 滚到底：最后一张卡底边离动作行顶边 **14.2px**（进货，展开「批次信息」后 max=153）、
  **14.0px**（记账）——正好一个 `--yh-page-gap`。
- 按钮高度 56px ≥ 44；无横向溢出；进货保存（Toast + 列表 10→11）与收摊结账流程均正常。
- 截图：`docs/screenshots/action-row/`（7 页 × 0%/100% + 进货压力位 + 动作行特写 + 结账流程 + 编辑态）。
