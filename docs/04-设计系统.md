## 1. 设计上下文

### 1.1 用户与场景

| 维度 | 事实 | 设计后果 |
|---|---|---|
| 用户 | 两个人（摊主与家人），非专业财务 | 文案说人话；危险操作二次确认；不暴露"借/贷/科目" |
| 设备 | 手机为主，平板为辅，竖屏单手 | 拇指热区优先；关键动作在屏幕下半部；44px 触控下限 |
| 环境 | 春节摊位，夜间、低温、可能戴手套、强光/弱光交替 | 暗色为默认；高对比；大数字；少而准的动效 |
| 网络 | 断网是常态，联网是偶然 | 所有反馈先本地确认，再提示同步；不出现阻塞式 loading |
| 任务 | 3 秒内完成一次加购；30 秒录完一张送货单；收摊对现金 | 商品卡一屏可点；进货表单连续录入；报表首屏给现金与毛利 |
| 情绪 | 忙、吵、怕算错 | 金额永远是视觉最高级；成功反馈短促明确；错误必须可撤销 |

### 1.2 品牌调性

**夜间余烬（Ember at Night）**：深蓝黑的夜空底 + 烟花橙的爆点 + 半透明玻璃的摊位灯箱感。
不是"科技蓝紫"，不是"节日大红"，而是**收摊后灯还亮着的那盏灯**——克制、温暖、可信。

三个可被记住的锚点：

- **橙只给钱与主操作**：价格、销售额、选中态、主按钮。橙色一出现，用户就知道"这是要看的/要点的"。
- **玻璃只做容器**：卡片、浮条、弹层是半透明的"灯箱"，不做发光边框、不做彩虹渐变。
- **数字有专属字体行为**：所有金额与数量用 `tabular-nums`，列与列对齐，数字变化不抖动。

### 1.3 设计原则（冲突时的排序）

1. **算得清 > 好看**：金额、数量、库存的层级永远优先于装饰。
2. **一只手 > 两只手**：主操作落在拇指区，底部导航与结算条常驻。
3. **离线是默认**：任何交互不得等待网络；同步状态是"告知"，不是"门槛"。
4. **少一次思考 > 少一次点击**：默认值、记忆操作人、保留购物车，减少重复决策。
5. **可撤销 > 弹窗确认**：能撤销的用 Toast 撤销；只有不可逆操作才拦截。

## 2. 设计令牌

### 2.1 三层架构

```
Primitive（原始值）         Semantic（语义）              Component（组件）
--yh-orange-500      →     --yh-ink-price          →     --yh-nav-title-size
--yh-ink-dark-2      →     --yh-ink-2              →     --yh-product-card-min
--yh-space-4         →     --yh-gap-card           →     --yh-dock-max
--yh-radius-xl       →     --yh-cart-radius        →     --yh-sheet-max-height
```

- **Primitive**：色阶、字号、间距、圆角、时长。只在 `tokens.css` 第 1 段出现，页面与组件禁止引用。
- **Semantic**：`ink / surface / border / accent / state / shadow / focus`。随主题切换，是唯一允许跨组件共享的颜色入口。
- **Component**：只服务一个组件族的尺寸与节奏。允许出现 2px 级光学值，但必须命名并写明理由。

命名规则：`--yh-<类别>-<语义>-<档位>`，全小写连字符；档位用数字（1 最弱、5 最强）或尺寸缩写（xs/sm/md/lg/xl）。禁止 `--yh-color-1`、`--yh-big` 这类无意义命名。

### 2.2 颜色

#### 2.2.1 品牌与中性色阶

| Primitive | 值 | 用途 |
|---|---|---|
| `--yh-orange-500` | `#ff8a00` | 品牌主色、主按钮、选中态、库存角标 |
| `--yh-orange-400` | `#ffa233` | 暗色悬停 |
| `--yh-orange-600` | `#e07200` | 亮色悬停 |
| `--yh-orange-800` | `#8a3f00` | 亮色金额文字、亮色焦点环 |
| `--yh-orange-100/200/300` | `#ffe8c7 / #ffd39b / #ffbb6b` | 暗色金额文字、浅色底纹 |

中性墨阶分暗/亮两条，语义层按主题取：

| 语义 | 暗色 | 亮色 | 角色 |
|---|---|---|---|
| `--yh-ink-1` | `#ffffff` | `#0f1f2a` | 标题、商品名、主数字 |
| `--yh-ink-2` | `#d6e0e2` | `#4a575c` | 辅助文字、库存、说明 |
| `--yh-ink-3` | `#a8b6ba` | `#5f6d73` | 占位符、三级注记 |
| `--yh-ink-4` | `#7f8f94` | `#7b878c` | 禁用文字（不用于正文） |

#### 2.2.2 语义色与实测对比度

对比度按 WCAG 2.x 相对亮度公式实算；底色取暗色 `#0e2530`（玻璃最深叠加近似）与亮色 `#eef2f6`。

| 语义 | 暗色值 | 暗色对比 | 亮色值 | 亮色对比 | 用在哪 |
|---|---|---|---|---|---|
| `--yh-ink-price` | `#ffb15c` | **8.82:1** | `#8a3f00` | **6.69:1** | 价格、销售额、合计、找零 |
| `--yh-ink-ok` | `#7ee2a8` | **10.05:1** | `#0f7a3d` | **4.82:1** | 正毛利、同步成功 |
| `--yh-ink-bad` | `#ff9b9b` | **7.85:1** | `#b3261e` | **5.81:1** | 负毛利、超卖、危险操作文字 |
| `--yh-ink-warn` | `#ffd27a` | **11.13:1** | `#8a5a00` | **5.27:1** | 临期、同步警告 |
| `--yh-ink-accent` | `#ffc27a` | **9.6:1** | `#8a3f00` | **6.69:1** | 选中 Tab、品牌强调文字 |
| `--yh-on-accent` | `#2a1600` | **7.33:1**（橙底） | `#2a1600` | **7.33:1**（橙底） | 主按钮/角标文字 |

**为什么主按钮用深墨字而不是白字**：白字在 `#ff8a00` 上只有 **2.36:1**，正文级不达标；`#2a1600` 达 **7.33:1**，且视觉上更像"烫金"，与夜间余烬一致。

**已知取舍**：GlassKit 默认危险色 `#ff3b30` 在暗底仅 **4.46:1**（低于 4.5），因此所有危险"文字"统一走 `--yh-ink-bad`，`--gl-color-error` 只留给图标与描边。

#### 2.2.3 表面与描边

表面不自己定义 rgba，直接映射 GlassKit，保证玻璃厚度一致：

| 语义 | 来源 | 用途 |
|---|---|---|
| `--yh-surface-1` | `--gl-surface-1`（白 8%） | 代码块、最内层 |
| `--yh-surface-2` | `--gl-surface-2`（白 10%） | 卡片、统计块、商品卡 |
| `--yh-surface-3` | `--gl-surface-3`（白 14%） | 图标按钮、浮条底 |
| `--yh-surface-4` | `--gl-surface-4`（白 16%） | 浮条、步进器 |
| `--yh-surface-5` | `--gl-surface-5`（白 22%） | 按下态 |
| `--yh-border-subtle` | `--gl-border-subtle` | 内部分隔、购物车行 |
| `--yh-border-medium` | `--gl-border-medium` | 卡片描边（统一 1.5px） |
| `--yh-border-strong` | `--gl-border-strong` | 浮条、复选框 |
| `--yh-border-accent` | 橙 45%/55% | 示例提示、选中强调 |

**规则**：同一层级只用一种描边。卡片 = `medium`，内部区块 = `subtle`，浮条 = `strong`。不允许"再加一层 1px 白边"制造层次。

#### 2.2.4 焦点环

| 主题 | 值 | 对底色对比 |
|---|---|---|
| 暗色 | `#ffc27a` | ≈ 9:1 |
| 亮色 | `#8a3f00` | 6.69:1 |

旧实现亮色焦点环是 `#ffd9a8`，在浅底上仅约 **1.4:1**，达不到 WCAG 2.4.11 的 3:1。现已全量替换为 `--yh-focus-ring`，宽度 2px、偏移 3px（复选框偏移 2px）。

### 2.3 排版

#### 2.3.1 字体

```css
--yh-font-sans: -apple-system, BlinkMacSystemFont, 'SF Pro Display',
  'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', system-ui, sans-serif;
--yh-font-mono: ui-monospace, 'SF Mono', 'Cascadia Mono', Consolas, monospace;
```

- **不加载网络字体**：断网首屏不闪、不产生 3G 体积、中文字形无回退空洞。
- 金额与数量**不换字体**，只开启 `font-variant-numeric: tabular-nums`。换等宽字体会让"¥"与中文混排断裂。
- 代码/同步码用 `--yh-font-mono`（`--gl` 组件已内置）。

#### 2.3.2 字号阶梯

| 令牌 | 值 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `--yh-text-2xs` | 11px | 1.45 | 500/600 | 角标、商品卡规格、Tab 标签 |
| `--yh-text-xs` | 12px | 1.45 | 400/500 | 辅助文字、表格次要列、时间 |
| `--yh-text-sm` | 13px | 1.5 | 400 | 说明、表单提示、收银明细 |
| `--yh-text-md` | 14px | 1.5 | 400/600 | 表单标签、列表副标题、导航胶囊 |
| `--yh-text-base` | 15px | 1.45 | 600 | 正文、商品名、购物车行标题 |
| `--yh-text-lg` | 18px | 1.35 | 600 | 卡片区标题 |
| `--yh-text-xl` | 20px | 1.3 | 600 | 副标题、统计中号数字、商品价格 |
| `--yh-text-2xl` | 24px | 1.2 | 600 | 弹层金额、找零、移动端主数字 |
| `--yh-text-3xl` | 30px | 1.15 | 600 | 报表销售额/毛利 |
| `--yh-text-4xl` | 40px | 1.1 | 600 | 收款完成金额 |

组件专用字号（不进阶梯，必须命名）：

| 令牌 | 值 | 理由 |
|---|---|---|
| `--yh-nav-title-size` | 22px | 顶栏宽度有限，24px 会挤压返回/主题按钮 |
| 320 压缩档 Tab 标签 | 10px | 仅 `≤380px`，是唯一允许低于 11px 的文本 |

#### 2.3.3 字重

只用三档：`400`（正文）、`500`（标签/次要强调）、`600`（标题与金额）。
**禁止 650/700/800**。中文在 700 下笔画粘连，玻璃背景上会糊；600 已足够建立层级。
金额不用 700 建立层级，而是用**字号 + 颜色 + tabular-nums** 三件事叠加。

|---|---|---|
| 页面标题 | 22 / 600 / 1.3 | 顶栏「开单」 |
| 区块标题 | 20 / 600 / 1.35 | 「单品毛利」「临期预警」 |
| 卡片标题 | 18 / 600 / 1.35 | 弹层内分组标题 |
| 列表主文 | 15 / 600 / 1.45 | 商品名、操作人 |
| 列表副文 | 13 / 400 / 1.5 | 规格、批号、同步状态 |
| 辅助注记 | 12 / 400 / 1.45 | 日期、设备名、FIFO 说明 |
| 角标 | 11 / 600 / 1 | 购物车件数、临期标签 |

### 2.4 间距

基准 4px，阶梯：`2 / 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。

| 令牌 | 值 | 典型用途 |
|---|---|---|
| `--yh-space-0-5` | 2px | 仅光学微调（数字槽、复选框勾） |
| `--yh-space-1` | 4px | 图标与文字、卡内最小间隔 |
| `--yh-space-2` | 8px | 同组元素、胶囊间距、按钮内纵向 |
| `--yh-space-3` | 12px | 卡片内边距、列表行内距 |
| `--yh-space-4` | 16px | 页面左右边距、区块内边距 |
| `--yh-space-5` | 20px | 大区块分隔（少用） |
| `--yh-space-6` | 24px | 页面级留白、弹层顶部 |
| `--yh-space-8` | 32px | 空状态上下、浮条左右收进 |
| `--yh-space-10/12/16` | 40/48/64 | 极少数大留白（引导页、空状态） |

**光学补偿档（重要）**：玻璃卡片有 1.5px 描边 + 8px 阴影，实际感知间距比 CSS 值大 2px。因此：

- `--yh-page-gap: 14px`（3.5 档）：页面纵向卡片间距，感知约 16px。
- `--yh-gap-card: 10px`（2.5 档）：卡片网格与行内间距，感知约 12px。

这两档是**有意为之**，不是遗留脏值；除它们之外，布局不得出现 14/10 的临时值。
组件内部允许 `calc(var(--yh-space-3) + 2px)` 这类表达，含义是"12px 基准 + 1.5px 描边的光学补偿"。

### 2.5 圆角、阴影、动效、层级

#### 2.5.1 圆角

| 令牌 | 值 | 用途 |
|---|---|---|
| `--yh-radius-xs` | 8px | 复选框 |
| `--yh-radius-sm` | 12px | 代码块、内嵌小面板 |
| `--yh-radius-md` | 16px | 收银明细、找零、价格预览、小卡 |
| `--yh-radius-lg` | 18px | 统计块、购物车行、首启提示 |

图标圆角 14px 是**图形资产规范**（44 × 0.318），不属于布局圆角。

#### 2.5.2 阴影

| 令牌 | 暗色 | 亮色 | 用途 |
|---|---|---|---|
| `--yh-shadow-1` | `0 1px 2px rgba(0,0,0,.24)` | `0 1px 2px rgba(15,31,42,.06)` | 贴地小元素 |
| `--yh-shadow-2` | `0 8px 32px rgba(0,0,0,.18)` | `0 8px 32px rgba(15,31,42,.08)` | 卡片、商品卡（默认海拔） |
| `--yh-shadow-3` | `0 16px 40px rgba(0,0,0,.42)` | `0 16px 40px rgba(15,31,42,.14)` | 弹层/模态 |
| `--yh-shadow-dock` | `0 12px 32px rgba(0,0,0,.4)` | `0 12px 32px rgba(15,31,42,.16)` | 结算浮条（唯一"漂浮"元素） |

**海拔规则**：页面内容只用 1/2；浮动操作条用 dock；弹层用 3。不允许卡片 + 卡片 + 阴影三层堆叠制造深度，深度由**玻璃透明度 + 描边**表达。

#### 2.5.3 动效

| 令牌 | 值 | 用途 |
|---|---|---|
| `--yh-dur-fast` | 150ms | 按下、箭头旋转、颜色过渡 |
| `--yh-dur-base` | 220ms | 浮条进入、常规状态切换 |
| `--yh-dur-sheet` | 260ms | 弹层进出（与 kit.tsx 的 260ms 一致） |
| `--yh-dur-slow` | 300ms | 页面级过渡（少用） |
| `--yh-ease-standard` | `cubic-bezier(.2,.8,.2,1)` | 默认 |
| `--yh-ease-out` | `cubic-bezier(.16,1,.3,1)` | 进入 |
| `--yh-ease-in-out` | `cubic-bezier(.4,0,.2,1)` | 对称位移 |

规则：

- 位移 ≤ 14px（浮条进入正好 14px），缩放 0.965–1，不做弹跳/回弹。
- 只动 `transform / opacity / background / border-color`，不动宽高与 `top/left`。
- `prefers-reduced-motion: reduce` 下：所有过渡降到 0.01ms，浮条动画关闭，保留颜色与透明度反馈。

#### 2.5.4 层级

| 令牌 | 值 | 用途 |
|---|---|---|
| `--yh-z-nav` | 40 | 吸顶导航 |
| `--yh-z-dock` | 900 | 结算浮条 |
| `--yh-z-sheet` | 1000 | 底部弹层遮罩 |
| `--yh-z-toast` | 1100 | 提示条（永远最上） |

GlassKit 的 Tab Bar 使用库内层级（约 100），低于浮条，符合"浮条压在 Tab 上方"的现有表现。

### 2.6 主题映射

`:root` 即暗色（默认），`[data-theme='light']` 只覆盖**语义层**。组件与页面不写主题分支。

| 语义 | 暗色 | 亮色 |
|---|---|---|
| `--yh-canvas` | `#070a10` | `#eef2f6` |
| `--yh-canvas-mid` | `#0e2530` | `#f5f7fa` |
| `--yh-ink-1..4` | 白 → `#7f8f94` | `#0f1f2a` → `#7b878c` |
| `--yh-accent` | `#ff8a00` | `#ff8a00` |
| `--yh-accent-hover` | `#ffa233` | `#e07200` |
| `--yh-focus-ring` | `#ffc27a` | `#8a3f00` |
| `--yh-shadow-2` | 黑 18% | 深蓝灰 8% |
| `--yh-aurora-1..3` | 余烬橙 16/14/10% | 暖橙 22/14/20% |

同时桥接 GlassKit 内部令牌（`--gl-color-text-muted`、`--gl-placeholder`、`--gl-color-on-primary`、`--gl-focus-ring`、`--gl-tab-bar-*`、`--gl-bg-aurora-*`），保证库组件与应用层同一套语义。

**换品牌只改两处**：`--yh-orange-500` 与 `--yh-orange-600`（以及 `--gl-color-primary` 的引用）。金额墨色、焦点环、极光会自动跟随派生；若新品牌亮度差异大，需重跑 6.2 的对比度表。

### 2.7 代码接入

```tsx
// src/main.tsx —— 顺序固定：库 → 令牌 → 应用层
import '@jungherz-de/glasskit/glasskit.min.css';
import './tokens.css';
import './styles.css';
```

```css
/* 业务样式写法 */
.price { color: var(--yh-ink-price); font-size: var(--yh-text-xl); font-variant-numeric: tabular-nums; }
```

## 3. 视觉层级系统

### 3.1 页面层级模型

每个页面最多四层，自上而下权重递减：

```
L0 全局导航   顶栏标题 22/600 · Tab Bar · 同步状态（只在更多页）
L1 任务焦点   一个页面只有一个：商品网格 / 进货表单 / 报表主数字 / 购物车
L2 支撑信息   分类胶囊、搜索、统计块、收款明细
L3 注记       日期、FIFO 说明、设备名、示例提示
```

规则：**同一屏不允许出现两个 L1**。开单页的 L1 是商品网格，结算浮条只是"动作入口"，不再抢标题级字号；报表页的 L1 是销售额与毛利两个主数字，其余压到 L2。

### 3.2 信息权重的四种手段（按优先级）

1. **字号**：相邻层级差 ≥ 2px（15 → 18 → 20 → 24 → 30）。
2. **颜色**：金额用 `ink-price`，状态用 `ink-ok/bad/warn`，其余用 `ink-1/2/3`。
3. **字重**：只差一档（400 / 500 / 600），不靠加粗堆层级。
4. **空间**：用 16/24px 留白分隔组，而不是加分割线；分割线只在表格与收银明细出现。

### 3.3 色彩语义角色（禁止串用）

| 颜色 | 唯一角色 | 不允许 |
|---|---|---|
| 烟花橙 | 主操作、选中态、金额、品牌 | 作为正文、作为错误提示 |
| 绿 | 正毛利、同步成功 | 作为"确认按钮"（确认是主操作，用橙） |
| 红 | 负毛利、超卖、不可逆操作文字 | 作为普通删除图标（图标用 `ink-2`） |
| 黄 | 临期、离线警告 | 作为可点击元素 |
| 中性墨 | 所有正文与结构 | 用纯黑 `#000`（暗色下发灰、亮色下过硬） |

### 3.4 空间节奏

- **页面**：左右 16px，卡片纵向 14px（光学 16），首屏顶部 4px。
- **卡片内**：18/16px（纵/横），紧密卡 14px。
- **组内**：8px；同组文字行 4px。
- **控件**：高度 52（输入）/ 56（按钮）/ 44（图标与胶囊）。
- **节奏对比**：卡片之间 14，卡片内部 12，形成"外松内紧"；禁止全局等距 16，否则所有内容糊成一片。

### 3.5 金额的专门规则

| 场景 | 字号 | 颜色 | 附加 |
|---|---|---|---|
| 商品卡价格 | 20 / 600 | `ink-price` | `¥` 与数字同色 |
| 结算浮条合计 | 20 / 600 | `ink-price` | 右对齐，`aria-live="polite"` |
| 弹层金额/找零 | 24 / 600 | `ink-price` 或 `ink-1` | 找零缺省显示「—」 |
| 报表主数字 | 30 / 600 | `ink-price` / `ink-ok` / `ink-bad` | 毛利缺失显示「—」并注明"成本待补" |
| 收款结果 | 40 / 600 | `ink-price` | 居中，唯一使用 40px 的地方 |

金额一律 `font-variant-numeric: tabular-nums`；不带千分位（摊位场景金额小，千分位反而增加噪声）；¥ 与数字之间不留空格。

### 4.3 表单

**Field（标签 + 控件 + 提示/错误）**

- 自动 `useId` 生成 `id`，`label[for]` 关联；错误/提示挂 `aria-describedby`。
- 错误时给控件加 `.glass-input--error`，错误文字放控件下方 4px，颜色 `ink-bad`，字号 12。
- 标签 14/500 `ink-2`；必填不加星号，改用文案说明（本产品无必填星号体系）。

**Input**

| 项 | 规格 |
|---|---|
| 高度 | 52px（`--gl-control-height`） |
| 圆角 | 14px |
| 背景 | `surface-2`，描边 `border-subtle` |
| 聚焦 | 2px `focus-ring`，不改变尺寸 |
| 占位符 | `ink-3`，对比 ≥ 4.7:1 |
| 数字输入 | `inputMode="decimal"` / `"numeric"`，不弹全键盘 |
| 错误 | 描边 `ink-bad` + 下方提示；不抖动、不弹窗 |

**Checkbox**：24px，圆角 8，选中填橙 + 深墨勾，焦点环 2px，整行 `label` 可点，行高 ≥ 44。

**Segmented（当日/全部、个/箱）**：容器胶囊，选项最小高 44，选中用橙色底 + 深墨字；`aria-pressed` 同步。

**Chip / Badge（分类、快捷金额）**：最小高 44，横向滚动不换行，隐藏滚动条但保留惯性；选中 `aria-pressed="true"`；`padding: 0 14px`。

### 4.4 导航

**顶栏**

- 吸顶，`z-index: 40`，高度 = 44 控件 + 上下 10px + 安全区。
- 结构：左（品牌图标 44 / 返回胶囊 44）— 中（标题 22/600，左对齐）— 右（主题切换 44）。
- 背景：暗色 `canvas 90% → 0` 渐变 + 16px 模糊；亮色固定浅色渐变，保证滚动时标题可读。
- 返回按钮 `aria-label="返回"`，主题按钮 `aria-label="切到浅色/切到深色"`。

**Tab Bar**

- 5 项，悬浮胶囊，距底 16px + 安全区；图标 24，标签 11/600（选中）/11/400。
- `aria-current="page"` 标记当前项；图标 `aria-hidden`。
- 切换 Tab 不销毁购物车与操作人（状态提升到 App + sessionStorage）。
- 商品/历史/设置是二级页，进入后隐藏 Tab Bar，用顶栏返回。

**列表行**

- 最小高 56，圆角随容器（列表外层 18/24），分隔线从文字起点开始。
- 整行可点：`role="button"` + `tabIndex=0` + Enter/Space 触发（`rowProps`）。
- 前置图标 22，后置 chevron 18，均 `aria-hidden`。

### 4.5 反馈

**Toast**

| 语气 | 图标 | 时长 | 关闭 | 角色 |
|---|---|---|---|---|
| success | 对勾 | 2600ms | 无（可带撤销） | `status` / `polite` |
| warning | 三角 | 4000ms | 无 | `status` / `polite` |
| error | 叉 | 5200ms | 有 | `alert` / `assertive` |
| 带动作 | 同语气 | 6000ms | 视语气 | 动作按钮 ≥ 44 |

位置：顶栏下方（`safe-area + 78px`），不遮挡标题；同一时间只保留一条，新消息替换旧消息并重置计时。

**Sheet（底部弹层）**

- 最大高 90dvh，圆角 24，`role="dialog"` + `aria-modal` + `aria-labelledby`。
- 焦点陷阱、Esc 关闭、关闭后焦点归还触发元素、锁定 body 滚动并恢复位置。
- 进入/退出 260ms；遮罩 `scrim`；点击遮罩关闭，点击面板内不关闭。
- 内容超长只滚 body，底部主按钮常驻。

**Empty（空状态）**

- 图标 24（`ink-2`）+ 一句可执行的话，不做"暂无数据"。
- 例："没有匹配的商品，先去「更多 → 商品」里添加"、"这段时间还没卖东西"。
- 可选动作按钮（secondary/sm）。

**Status（错误/警告条）**：玻璃面 + 语气色图标 + 说明，用于"成本待补""同步失败"这类需要解释而非打断的场景；不用弹窗。

### 4.6 数据展示

**Card**：圆角 24，内边距 18/16，`surface-2`，1.5px `border-medium`，`shadow-2`。`flush` 变体只用于包列表/表格（内部自带行距）。

**Stat**：圆角 18，内边距 12/14，标签 12 `ink-2`，数值 20/600 `tabular-nums`；`tone` 只接受 brand/ok/bad；hero 变体 30px。

**Money**：`¥` + 两位小数，`tabular-nums`，不缩写、不加千分位。

**Table**：数字列右对齐 + `tabular-nums`；表头 12/500 `ink-2`；行高 ≥ 44；≤380px 隐藏"成本"列（`.hide-sm`），信息不丢失（可在详情看）。

**List**：外层 18/24，行 56，副标题 13 `ink-2`；可交互行有按下态与焦点环。

**Badge**：胶囊，11/600；语义色只用于状态（临期黄、过期红、示例橙），不用于分类。

**商品卡**：2 列（<520）/ 3 列（≥520），最小高 108，圆角 24，内部 4px 节奏；名称 15/600（最多 2 行）、价格 20/600 橙、规格与库存 11 `ink-2`；库存为负加 `.low` 变红；焦点环 2px。

**购物车行**：圆角 18，内边距 12/14；上行名称/单价 + 金额/删除（删除 44）；下行单位分段 + 步进器 + 改价；控件换行，320 不裁切。

**结算浮条**：固定底部（Tab + 74px + 安全区），宽 = 视口 − 32，最大 528，胶囊，`shadow-dock`，`z-index: 900`；左侧件数可点开购物车，中间合计 20/600，右侧主按钮"结算"；进入动画 220ms / 14px。

### 4.7 状态规范总表

| 状态 | 通用处理 | 组件差异 |
|---|---|---|
| Default | 见各组件 | — |
| Hover | 仅指针设备；亮度/背景 +4% | 商品卡同时提亮描边 |
| Active | 缩放 0.98 或背景加深 | 商品卡 0.965 |
| Focus | 2px 环 + 3px 偏移，环色分主题 | 复选框 2px 偏移 |
| Disabled | 透明度 45%，禁用交互与投影 | 主按钮保留文字对比 |
| Loading | 禁用 + 文案替换；列表用骨架屏 | 开单保存中不关闭弹层 |
| Error | 就地提示，不清空输入 | 表单下方 12px 红字 |

**关于骨架屏**：商品/库存列表数据来自本地 IndexedDB，通常 < 100ms，不显示骨架屏（会闪）。只有首次启动"正在打开账本…"用 Empty 形式占位；云同步永不阻塞列表。

### 4.8 组件扩展规则

新增组件必须回答四个问题：

1. 它解决哪个已存在的任务？能否用现有组件组合？
2. 它的令牌归属（语义/组件）是什么？需要新增哪些令牌？
3. 五个状态（default/hover/active/focus/disabled）与 loading/error/empty 是否齐全？
4. 320 / 390 / 768 / 1024 四个宽度下如何表现？

不满足则不进入组件库，先在页面内实现并在下个版本评审。

## 5. 响应式设计

### 5.1 断点体系

CSS 变量不能进入 `@media`，断点是**常量**，改动必须同步本表与 CSS。

| 名称 | 范围 | 设计策略 | 当前实现 |
|---|---|---|---|
| xs 极窄 | < 380px | 压缩档：表格 12px、隐藏成本列、hero 数字 24、Tab 标签 10px | ✅ `@media (max-width: 380px)` |
| sm 基础 | 380–519px | 单列；商品卡 2 列；页面边距 16 | ✅ 默认 |
| md 密度 | 520–639px | 商品卡 3 列；统计块 4 列 | ✅ `@media (min-width: 520px)` |
| lg 平板 | 640–1023px | 容器仍 560，居中；竖屏手持优先 | ✅ 容器上限 |
| xl 桌面 | 1024–1279px | 规划：容器 720，商品区 + 购物车常驻双栏 | ⏳ v1.1 |
| 2xl 大屏 | ≥ 1280px | 规划：容器 960，报表卡片并排 | ⏳ v1.1 |

**为什么 520 是密度断点而不是设备断点**：商品卡从 2 列变 3 列取决于"单卡最小可读宽度 170px × 3 + 间距 + 边距"，与设备类型无关。设备断点（640/1024）只决定容器与布局结构。

### 5.2 容器与网格

```css
--yh-page-max: 560px;   /* 内容最大宽度 */
--yh-page-pad: 16px;    /* 左右安全边距 */
--yh-page-gap: 14px;    /* 卡片纵向节奏（光学 16） */
--yh-gap-card: 10px;    /* 网格/行内节奏（光学 12） */
```

- 容器居中：`max-width + margin: 0 auto`，两侧不留死白。
- 12 列心智模型，实际用 2/3/4 等分网格：商品卡 2→3 列，统计 2→4 列，收款行 1 列。
- 网格最小列宽 0：`repeat(n, minmax(0, 1fr))`，防止长商品名撑破。
- 浮条宽度 = `100% − 32px`，最大 528，始终比容器窄 32，形成"悬浮"感。

### 5.3 组件适配表

| 组件 | 320–379 | 380–519 | 520–639 | 640–1023 | 1024+（规划） |
|---|---|---|---|---|---|
| 顶栏标题 | 22 | 22 | 22 | 22 | 22 |
| 商品卡 | 2 列 | 2 列 | 3 列 | 3 列（容器 560 内） | 4 列 |
| 统计块 | 2 列 | 2 列 | 4 列 | 4 列 | 4 列 |
| 报表 hero | 24 | 30 | 30 | 30 | 30 |
| 表格 | 隐藏成本列，12px | 全列，13px | 全列 | 全列 | 全列 |
| 购物车控件 | 换行，gap 6 | 换行，gap 8 | 单行 | 单行 | 单行 |
| 结算浮条 | 宽 −32，胶囊 | 同左 | 同左 | 同左 | 右侧常驻面板 |
| Tab Bar | 悬浮，10px 标签 | 11px | 11px | 11px | 左侧 Rail（规划） |
| Sheet | 全宽底部 | 全宽底部 | 最大 560 居中 | 最大 560 居中 | 480 侧滑（规划） |

### 5.4 平板与桌面策略

**v1 的决定：不急于做双栏。** 摊位场景平板以竖屏为主，560 单列能让商品卡保持 3 列、拇指可达、结算浮条居中，实际效率高于把购物车摊到右侧。强行双栏会让"加购 → 结算"的视线路径变长。

**v1.1 双栏触发条件**（同时满足才做）：

1. 真机试用（M6）反馈"横屏/大屏加购效率低"；
2. 购物车状态已完全提升到 App（现已满足）；
3. 有 ≥ 1024 宽度的真实使用记录。

双栏结构预案：左 60% 商品网格 + 分类，右 40% 常驻购物车（含合计与结算），Tab Bar 改为左侧 Rail；报表页改为两列卡片。

### 5.5 安全区与软键盘

- 使用 `100dvh` 而非 `100vh`，避免移动浏览器地址栏导致底部被裁。
- 顶栏 padding-top、底部导航/浮条 bottom 均叠加 `env(safe-area-inset-*)`；`index.html` 已设 `viewport-fit=cover`。
- 输入框字号不小于 16px（GlassKit 默认），避免 iOS 聚焦自动放大；日期输入固定 40px 高是例外，见 6.7。
- 弹层打开时锁定 body 滚动并记录 `scrollY`，关闭后恢复，避免 iOS 跳动。

| 4.1.2 名称角色值 | 可访问名 | 图标按钮均有 `aria-label` | ✅ |
| 4.1.3 状态消息 | 可被播报 | Toast `role=status/alert` + `aria-live` | ✅ |
| 2.3.3 动画 | 可关闭 | `prefers-reduced-motion` | ✅ |

### 6.2 对比度实测（发布前必须复跑）

| 组合 | 对比度 | 结论 |
|---|---|---|
| 价格墨 `#ffb15c` / `#0e2530` | 8.82:1 | AA |
| 正文 `#d6e0e2` / `#0e2530` | 11.78:1 | AA |
| 三级文字 `#a8b6ba` / `#0e2530` | 7.59:1 | AA |
| 成功 `#7ee2a8` / `#0e2530` | 10.05:1 | AA |
| 危险 `#ff9b9b` / `#0e2530` | 7.85:1 | AA |
| 警告 `#ffd27a` / `#0e2530` | 11.13:1 | AA |
| 亮色价格 `#8a3f00` / `#eef2f6` | 6.69:1 | AA |
| 亮色正文 `#4a575c` / `#eef2f6` | 6.65:1 | AA |
| 亮色三级 `#5f6d73` / `#eef2f6` | 4.76:1 | AA |
| 亮色危险 `#b3261e` / `#eef2f6` | 5.81:1 | AA |
| 主按钮墨字 `#2a1600` / `#ff8a00` | 7.33:1 | AA |
| 白字 / 橙底 `#ffffff` / `#ff8a00` | 2.36:1 | **禁用** |
| 旧危险色 `#ff3b30` / `#0e2530` | 4.46:1 | **不达 AA** |
| 旧亮色焦点环 `#ffd9a8` / `#eef2f6` | ≈1.4:1 | **不达 3:1** |

复算方法：sRGB → 线性化 → 相对亮度 → `(L1+0.05)/(L2+0.05)`。极光叠加会让底色变亮，**取最坏情况（最亮底色）**复算。

### 6.3 键盘与焦点

- Tab 顺序：返回/主题 → 搜索 → 操作人 → 分类 → 商品卡 → 浮条 → Tab Bar。
- 商品卡、列表行、分类胶囊均为原生 `button` 或带 `role="button"` + Enter/Space。
- Sheet：打开时焦点移入第一个可聚焦元素；Tab 循环；Esc 关闭；关闭后焦点回到触发元素。
- 浮条出现时不抢焦点（避免打断输入）；合计变化用 `aria-live="polite"`。
- 焦点环永不移除；不用 `outline: none`。

### 6.5 触控、缩放与高对比

- 所有按钮/胶囊/步进器/关闭按钮 ≥ 44 × 44；复选框 24 但整行 label 可点。
- 文字缩放 200%：卡片高度自适应，无 `overflow: hidden` 截断文字（商品名允许换行，价格不缩）。
- Windows 高对比模式：不依赖颜色单独传达状态，临期同时有文字"剩 3 天/已过期"，毛利同时有正负号与「—」。
- 横屏：容器仍 560 居中，内容不拉伸；浮条不遮挡内容（底部预留 150px）。

### 6.6 减动效

```css
@media (prefers-reduced-motion: reduce) {
  .checkout-dock { animation: none; }
  .prod-btn, .glass-tab-bar__item, .glass-btn, .glass-badge,
  .glass-input, .glass-pill, .icon-btn, .stepper button {
    transition-duration: 0.01ms !important;
  }
  .glass-sheet-overlay, .glass-sheet { transition-duration: 0.01ms !important; }
}
```

保留颜色/透明度变化作为反馈；去掉位移、弹层滑动、液滴动画的长尾。

### 6.7 已知限制（诚实清单）

1. **玻璃叠加的对比度是估算**：极光在最亮处叠加后底色会高于 `#0e2530`，若未来加强极光，需按最亮像素复算。
2. **日期输入 40px 高**：原生 `input[type=date]` 在部分浏览器无法稳定撑到 44，计划外包一层 44px 容器；当前仅在报表页出现。
3. **320 隐藏成本列**：信息未删除，可在销售记录详情查看；但表格视图下不可见，属于可接受取舍。
4. **10px Tab 标签**：仅 ≤380px，图标 + 文字同时存在，不承载唯一信息。
5. **GlassKit 内部阴影/高光不可完全令牌化**：库内 `--gl-gloss-*` 未覆盖，视觉以库版本为准；升级 1.4x 需重跑视觉回归。
6. **Toast 位于顶栏下方**：横屏且软键盘弹出时可能被压缩，错误 Toast 仍可通过关闭按钮操作。

### 7.2 新增令牌的标准流程

1. **说明缺口**：现有令牌为什么不能表达？（截图/场景）
2. **定层**：Primitive（新色阶/新档位）→ Semantic（新语义）→ Component（单组件尺寸）。
3. **命名**：按 2.1 规则；Component 令牌必须带组件名前缀语义（如 `--yh-dock-max`）。
4. **双主题**：Semantic 令牌必须同时给暗/亮值；只给一个主题视为未完成。
5. **对比度**：文本类新色必须实测 ≥ 4.5:1，非文本 ≥ 3:1，并把数值写进 6.2 表。
6. **落地**：先替换现有裸值，再删除旧值；保留别名不超过一个版本。
7. **记录**：更新 8.3 变更日志与本文档对应表格。
