# 云同步设置（Supabase）

> 目标：**云端有一份主账，离线照常开单，联网自动推拉**。
> 本机始终是“可离线工作的副本”；手动导出/导入降级为备份手段。

## 零配置（默认，开箱即用）

应用已经内置了项目 URL、publishable key 和同步码。**两台手机打开同一个网址就自动是同一本账，不需要填任何东西**。

- 设置页会显示「配置：内置，打开即用」
- 想换自己的同步码：设置与同步 → 云同步 → 修改配置（两台手机都换）
- 注意：内置同步码会随公开仓库的前端代码发布，理论上懂技术的人翻代码能看到；如果在意隐私，请换成自己的同步码

下面的手工配置步骤只在“换项目 / 换同步码”时需要。

## 一、为什么需要 Supabase

GitHub Pages 只能放静态文件，存不了账。Supabase 提供免费的 Postgres 数据库 + REST 接口，正好当同步后端。两台手机共用同一个 Supabase 项目和一个同步码。

## 二、配置步骤（约 3 分钟）

1. 打开 <https://supabase.com>，用 GitHub 登录，`New project`：
   - 名称随意，数据库密码记一下（后面一般不用）
   - Region 选 **Singapore**（离国内近）
   - 等 1 分钟项目初始化
2. 左侧 `SQL Editor` → 新建查询 → 把 [`supabase/schema.sql`](../supabase/schema.sql) 整段粘贴执行。
3. 左侧 `Project Settings → API`：
   - 复制 **Project URL**（形如 `https://xxxx.supabase.co`）
   - 复制 **anon public key**
4. 手机打开烟花账 → `更多 → 设置与同步` → **云同步**：
   - 填 Project URL、anon key
   - 点「生成」得到一个同步码
   - 「保存并启用」
5. 第二台手机填**同样的 URL、anon key、同步码**，保存启用。

两台都显示「已连接」后，一台开单，另一台几秒到十几秒内会自动看到。

## 三、自动同步的时机

- 打开 App / 切回前台
- 网络从断开变连通
- 每成交一单（本地写完后约 0.7 秒推送）
- 每 10 秒拉取一次对方的新记录

本地写入永远先成功，网络只影响“什么时候同步出去”，不影响开单。

## 四、同步什么、不同步什么

| 数据 | 同步 | 规则 |
|---|---|---|
| 商品 | 是 | 按 `updatedAt` 后写胜 |
| 进货批次 | 是 | UUID 并集，不覆盖 |
| 销售单/明细 | 是 | UUID 并集，只增不改；作废是订单上的标记 |
| 库存调整 | 是 | UUID 并集 |
| 设置（操作人、临期天数等） | 是 | 后写胜 |
| 设备名 / 设备 ID | 否 | 每台设备自己的身份 |

删除用“墓碑”记录（`deleted=true`）同步，另一端会删掉对应本地记录。

## 五、安全说明

- `anon key` 和同步码只存在手机本地（localStorage），**不写进代码仓库**。
- 数据库用 RLS 策略校验请求头 `x-ledger-key`：只有带着正确同步码的请求能读写对应账本。
- 如果 links 的 header 策略在你的项目里不生效，可以退回“单人账本”策略（见 schema.sql 末尾注释）——前提是项目只有你自己用、key 不外泄。
- 想换同步码：改两台手机的同步码即可；旧数据留在旧账本下，不会自动迁移。

## 六、常见问题

| 现象 | 排查 |
|---|---|
| 保存后显示「同步出错」 | 先点「测试连接」；确认 SQL 执行过、URL/key 没抄错 |
| 401 / 403 | 多半是 RLS 策略没建好，或 key 不是 anon public key |
| 一直「待推送 N 条」 | 检查网络；Supabase 免费项目长时间不用会暂停，去控制台恢复 |
| 第二台看不到新单 | 确认两台同步码完全一致（大小写/空格）；点「立即同步」试 |
| 数据想清空重来 | 设置与同步 → 清空全部数据，会问是否同时清云端 |

## 七、和手动备份的关系

手动「导出备份 / 导入合并」保留，用于：

- 云端出问题时的兜底
- 换手机/重装时恢复
- 存一份到微信收藏

云同步正常时不需要再手动合并。
