# 报表与对账 · 主动体验巡检（2026-11-12）

> 视角：烟花摊主，收摊后想弄清「今天赚了多少、钱对不对」。
> 环境：390×844 / DPR3 / touch / preview `127.0.0.1:4173` / `localStorage['yh-sync-disabled']='1'`。
> 方式：脚本直接把 20 单造进 IndexedDB（`scripts/ux-audit-20261112/plan.py`），再用 UI 实操取证；**未改任何源码**。
> 数字三方对照：Python 手算（plan.py）→ 浏览器里另一套 JS 算法扫库 → 页面 DOM 显示。

|---|---|---|---|

## 一、结论（摊主视角 5 句话）

1. 收摊后点开「报表」，**1 次点击、0.74 秒**就能看到大数字——但那个数是**另一场还没结账的 ¥16.00**，不是今天已结账的 ¥389.50，而且毛利写着「—」。
2. 想看到今天的账，得多点 **3 下**（历史场次 → 场次胶囊 → 选场次，共 2.02 秒），数字才对上；**报表上没有任何「今天合计」**，两场要自己加。
3. 现金/微信/支付宝三行**是对的**：206.00 + 89.00 + 94.50 = 389.50，2 笔作废单已正确排除（含进去会多 ¥83.00），合计打勾。
4. 但「这些钱里包含 2 笔删除、2 笔补记、¥63.00 让利」**没有任何一处说明**——只有一个不显示的「补过 2 单」小徽标，删除单在报表里像没发生过。
5. 更麻烦的是毛利：**整页毛利都成了「—」**，因为另一场（或别的商品）缺成本；而缺成本的行照样显示绿色正毛利（手持烟花棒 成本 ¥0 毛利 +¥20），成本列在 390 宽下还被藏了——估出来的利润会被当成真赚的。

## 二、6 个问题的实测答案

### Q1 3 秒内能找到「今天赚了多少」吗？

**步骤**：冷启动 → 点底部「报表」→ 看首屏。

**实测**
- 点击 **1 次**，从点 tab 到毛利渲染 **0.74 s**，**0 次滚动**（`app-main` 未滚动）。
- 首屏元素位置：毛利 y=208.4（可见）、收款四行 293–438（可见）、单数/让利/赠品 448–519（可见）、单品表从 778 才开始（需滚动）。
- 但显示的是 **「本场」= 11-12 22:00 → 进行中**（S2）：销售额 **¥16.00**，毛利 **—**，单数 2。
- 今天真正已结账的 S1 是 **¥389.50 / 毛利 —**，要按 3 下切过去（见 Q5）。
- 报表页全文**没有「今日 / 今天合计」字样**（`mentions_today_total: false`）。

**截图**：`01-report-first-screen.png`
**结论：不通过。** 3 秒内能看到一个数字，但那是「还没结账的另一场」，不是「今天赚了多少」；即使切对场次，毛利也是「—」。摊主极可能把 ¥16.00 当成一天的收入。

### Q3 作废 / 补记 / 让利是否可解释？

**实测**

**截图**：`03-report-summary-card.png`、`04-report-margin-table.png`
**结论：不通过（部分）。** 让利有汇总有分列；作废单等于不存在；补记只给一个数字，还是死徽标。摊主无法回答「这 389.50 里有没有不该算的」。

### Q4 异常能否被发现？

**步骤**：报表（S1）看单品表与提示条 → 去库存页 → 从报表出发找具体那一单。

**实测**
- **负毛利**：只有「组合烟花 36 发」毛利 `¥-6.00` 变红字（`rgb(255,155,155)`）；整表 `badgeOrIcon` 计数 **0**，没有图标、徽标、也没有「1 个商品亏本」的汇总句。报表全文不含「负毛利/亏损」。
- **成本缺失（`uncoveredQty=34`）**：提示条确实有：「有 34 个（基本单位）销量没有对应的进货批次（漏录进货或超卖）…毛利先显示为「—」」。但：
  - 这是**全局数**，和当前场次无关（见 Q5：S2 本场 0 缺失，照样显示 34 并让毛利变 —）；
  - 不说**是哪个商品**；
  - 缺成本的行在表里照样是**绿色正毛利**：手持烟花棒 成本 ¥0.00 / 毛利 **+¥20.00**；电光花 40 把里 30 把是估的 / 毛利 **+¥36.00**；
  - 390 宽下「成本」列 `display:none`（`hide-narrow` ≤520px），摊主连「成本 0」都看不到。
- **负库存**：报表页对负库存**只字未提**（仅提示条里出现「超卖」一词，不带商品）；库存页才显示「电光花 库存 -1 箱 · 负库存」「手持烟花棒 库存 -4 支 · 负库存」。
- **超大折扣（100 元卖 10 元）**：报表里只有「让利 ¥58.00」混在 ¥63.00 总和里，**无阈值、无异常标记**（`大折扣/异常单: false`）。

**定位具体哪一单**：报表 → 更多（1）→ 销售记录（2）→ 滚动到 16:30 → 点开（3）→ 详情写「1 个 × ¥10.00 · 让利 ¥58.00」。**3 次点击 + 1 屏滚动，2.61 s**；但报表没有给订单号/时间，同一商品 2 单（¥68 与 ¥10）要各点开一次才能确认。

**截图**：`04-report-margin-table.png`、`20-report-margin-table-390.png`、`05-stock-negative.png`、`06-history-list.png`、`07-history-order-detail.png`
**结论：不通过。** 唯一能被发现的异常是「负毛利变红」和一条全局成本提示；负库存、超大折扣、缺失成本的具体商品都没有出口，缺成本行还显示为绿色盈利。

### Q5 未结账的场次会不会混进来？切换几步、数字变不变？

**步骤**：冷启动 → 报表（默认）→ 记录 → 切历史场次 → 选 S1 → 再切回本场。

**实测**
- 默认「本场」= **S2（进行中）**：`11-12 22:00 → 进行中`，销售额 **¥16.00**，现金 ¥6.00 / 微信 ¥10.00，单数 2，毛利 **—**。
- 场次隔离是**对的**：S1 显示 ¥389.50（不含 S2 的 ¥16.00）；历史页日合计 ¥405.50 = 两场相加。
- 切换成本：**3 次点击**（历史场次 → 场次胶囊 → 选场次），**2.02 s**（含弹层动画）；选完 **120 ms 内**数字已变（无需刷新）。
- 切回「本场」立刻回到 ¥16.00。
- 场次弹层只有 1 个已结账场次：`2026-11-12 · 09:05 · 补过 2 单 | 16 单 · 销售额 ¥389.50`（进行中的场次不列出，合理）。
- 但报表**没有「今天两场合计」**；`本场` 这个名字在收摊后又指向「新开的下一场」，字面与摊主的「今天」不一致。
- 公平地说：若**没有**进行中的场次，「本场」会退回最近一场已结账（这条是对的）；问题只出现在「结完这场又开了下一场」——正是摊主守着摊、临时加场最常见的状态。

**截图**：`01-report-first-screen.png`（本场 S2）、`08-session-picker.png`、`09-report-closed-session.png`（切到 S1）
**结论：部分通过。** 数字隔离正确、切换即时、路径 3 步；但默认停在「下一场」，且没有按天汇总，收摊对账的第一步就走错。

## 三、发现的问题（按收益排序）

### H1 默认「本场」指向下一场，且没有「今天合计」
- **现象**：收摊后打开报表，看到 ¥16.00（22:00 新开那场），毛利「—」；今天已结账的 ¥389.50 藏在历史场次里，还要 3 步。整天收入（¥405.50）在任何地方都没有。
- **证据**：Q1（1 点击 / 0.74 s / ¥16.00 / `mentions_today_total:false`）、Q5（3 点击 / 2.02 s / 切后 ¥389.50）、历史页日合计 ¥405.50。
- **改法**：报表头加一行「今天 · 已结账 2 场，销售额 ¥405.50 · 毛利 ¥143.30（点开看场次）」，默认停在这行；「本场/历史场次」改名为「进行中 / 已结账」。数据现成：`sessionReport` 按 `closedAt` 落在今天的场次累加即可。
- **成本**：**M**（ReportPage 增加一个按日聚合的 useMemo + 一段 JSX；`calc.ts` 加 `dayReport(sessions, ...)`）。

### H2 毛利「—」是全局口径，且与「复制本场汇总」文本自相矛盾
- **现象**：只要任意一处缺成本，**所有场次**的毛利都显示「—」。S2 本场 0 个缺失，照样显示「毛利（成本待补）—」；同时「复制本场汇总」的文本却打印「毛利 ¥135.50」。
- **证据**：`ReportPage.tsx` 里 `const costMissing = fifo.uncoveredQty > 0;`（全局）；Q1/Q5 的 S2 显示 34 个缺失；`copy_toast` 实测文案 `…毛利 ¥135.50 · 让利 ¥63.00…`。
- **改法**：把口径改成按场次——`sessionMissingQty = Σ 该场明细的 uncovered`（fifo 里按 line 记 `uncoveredQtyByLine`），只有本场有缺失才把毛利变成「—」，并在提示条写「本场 30 把电光花 + 4 支手持烟花棒缺批次」；`copySummary` 与 hero 用同一个 `grossKnown` 判断，禁止一处显示 — 一处显示金额。
- **成本**：**M**（calc 增加按行/按场的 uncovered 汇总，ReportPage 两处判断共用）。

### H3 缺成本的行显示为绿色盈利，成本列还被隐藏
- **现象**：手持烟花棒（无批次）成本 ¥0.00、毛利 **+¥20.00** 绿色；电光花 40 把里 30 把是估算，毛利 **+¥36.00** 绿色。390 宽下「成本」列 `display:none`，连 0 都看不到。
- **证据**：Q4 表格行（`手持烟花棒 ¥20.00 / ¥0.00 / ¥20.00`）、`table_headers_visible` 中「成本 display:none」。
- **改法**：`ProductMargin.costIncomplete` 已存在但没赋值——给缺批次的行打「成本待补」小徽标（同「赠 1」的位置），毛利数字后加 `~`，并把该行排到最前；390 宽下把「成本」列恢复，改隐藏「赠品」列（赠品信息已在商品名下「赠 1」）。
- **成本**：**S**（calc 里 3 行赋值 + ReportPage 一行 JSX + 一条 CSS 断点）。

### M1 作废单在报表里彻底不存在
- **现象**：没有「已排除 2 笔删除 · ¥83.00」；只有作废单的场次显示「销售额 ¥0.00 / 单数 0 / 这一场还没卖东西」，像没开张。
- **证据**：Q3 `mentions_voided:false`；边界用例 `18-edge-only-voided.png` 全文无删除字样。
- **改法**：汇总卡底部加一行灰色小字「已排除 2 笔删除（¥83.00）· 可点开看」，点开一个 Sheet 列出被删单的时间/金额/撤销；`SessionSummary` 加 `voidedCount/voidedFen`（`sessionReport` 里顺手统计，现在只 filter 掉了）。
- **成本**：**S**（calc 加两个字段 + 卡片一行 + 复用 Sheet）。

### M2 补记徽标不可点、不带金额
- **现象**：「补过 2 单」是纯 `<span>`（`cursor:auto / tabIndex:-1`），不知道补的哪两单、补了多少钱。
- **证据**：Q3 `patched_badge_clickable`。
- **改法**：改成按钮（与「补记」并列）→ 点开 Sheet 列出 `createdAt > closedAt` 的单据与金额；徽标文案改「补记 2 单 · ¥13.50」。
- **成本**：**S**（span→button + 复用 Sheet，数据按 session 过滤即得）。

### M3 负毛利与超大折扣没有任何标记
- **现象**：只有数字变红；没有「1 个商品亏本」、没有折扣阈值提示；100 元卖 10 元（85% 折扣）只贡献到「让利 ¥63.00」。
- **证据**：Q4 `row_badge_or_icon_count:0`、`report_mentions.负毛利:false`、`大折扣:false`。
- **改法**：单品行毛利为负时加「亏」徽标；折扣率 ≥50% 的行加「大折扣」徽标；汇总卡在让利数字旁加一句「其中 1 单让利 ¥58.00（85%）」。
- **成本**：**S**（模板里两个条件渲染 + 一处 max 折扣计算）。

### M4 对账下钻路径缺失（无支付筛选 / 无时段 / 无搜索 / 删除单无金额）
- **现象**：现金少 50 元只能肉眼扫；历史页无支付方式与时段筛选、无搜索，日期内两场混排；已删除单显示「撤销」而不是金额。
- **证据**：Q6 全部计数为 0；`history.deletedRowShowsAmount:false`、`cashRowCount:11`。
- **改法**：历史页筛选条加第二行「全部 / 现金 / 微信 / 支付宝」（本地 filter，不动数据）；已删除行保留删除线同时**显示灰色金额**（`~~¥68.00~~`+撤销）；日标题的「N 单」改成「N 单（另有 2 笔已删除）」。
- **成本**：**M**（HistoryPage 一个 state + 两个 filter + 一行样式；与已修项无冲突）。

### M5 历史页日合计「20 单 · 合计 ¥405.50」口径打架
- **现象**：单数含 2 笔删除，金额不含；摊主用「405.50 ÷ 20」算不出任何东西。
- **证据**：Q6 日标题 + `voidedCount:2`；列表实际 18 笔计钱。
- **改法**：`{list.filter(o=>!o.voided).length} 单 · 合计 ¥405.50`，括号补「另有 2 笔已删除」。
- **成本**：**S**（一行模板）。

### M6 表头声称吸顶，实际会滚走
- **现象**：`position:sticky; top:0` 写在 `.glass-table thead th`，父层 `.glass-table-wrap{overflow-y:hidden}` 让它相对一个纵向不滚动的盒子定位；滚到 900px 时表头 `thTop=-48`，8 行数据看不到列名。
- **证据**：`sticky.json`（scroll_900/1200 → thTop -48，`header_pinned:false`）。
- **改法**：把 `overflow-y: hidden` 改成 `visible`（横向滚动用 `overflow-x:auto` 仍需一个滚动容器，可改为外层不加 `overflow`，用 `min-width` 让表格自身换行）；或把 sticky 提到卡片标题行上（`form-head--inset` 吸顶）。
- **成本**：**S/M**（CSS 一行 + 回归截图；若改结构则 M）。

### L1 场次切换控件在屏幕顶端，不在拇指区
- **现象**：分段按钮与场次胶囊 y≈87、高 44px；单手收摊时够不到（拇指舒适区 562 以下）。
- **证据**：`sticky.json` `controls.seasoned`（y 87/h 44）、`in_thumb_zone: [false,false]`。
- **改法**：把「本场/历史场次 + 场次胶囊」挪到汇总卡底部（毛利之后），或做成吸底小条；高度不动。
- **成本**：**S**（换 JSX 位置，无逻辑改动）。

### L2 成本提示条不区分场次
- **现象**：切到 S2（本场 0 缺失）仍显示「有 34 个…」，与 H2 同源但独立可见。
- **证据**：Q5 `default_banners` 含 34；S2 `uncoveredQty=0`。
- **改法**：并入 H2 的按场次口径；若坚持全局，则文案改成「全部场次共 34 个…（本场 0 个）」。
- **成本**：**S**（随 H2 一起改）。

## 四、建议先修的 3 条

1. **H1 默认场次 + 当日合计**：报表首行给「今天 · 2 场 · ¥405.50 · 毛利 ¥143.30」，默认停在这里。这是摊主收摊后的第一个动作，错一次后面全错。（M）
2. **H2 + M1 + M2 口径与三行说明**：毛利按场次算（不要再全局变 —）；汇总卡加一行可点开的「已排除 2 笔删除 ¥83.00 · 补记 2 单 ¥13.50 · 让利 ¥63.00」。一次改动同时消灭「毛利不可用」「删除不可见」「补记不可查」三个不信任点。（M）
3. **H3 把缺成本落到行**：缺批次的行打「成本待补」、毛利加 `~`、390 宽恢复「成本」列。现在它显示为绿色盈利，是会直接误导定价的错账。（S）

## 五、通过项（不凑数）

- **收款三行 + 合计校验准确**：206.00 + 89.00 + 94.50 = 389.50，与逐单相加、与二次扫库三方一致，差 0。
- **作废单正确排除**：含作废会多 ¥83.00（现金 +68、微信 +15），页面没有。
- **场次隔离正确**：S1 的 ¥389.50 不含 S2 的 ¥16.00；历史页日合计 ¥405.50 恰为两场之和。
- **切换后数字立即变**：选完场次 120 ms 内 hero/收款行全部换新，无需刷新、无闪烁。
- **单品毛利表自洽**：8 行销售额合计 389.50、成本合计 254.00、毛利合计 135.50，与汇总卡三处对上。
