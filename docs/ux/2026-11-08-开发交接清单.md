## 0. 交接摘要

### 0.1 这次改的是什么

不是给现有"开单页"换文案，而是把**实时收银模型**换成**事后补记台账模型**：

| 维度 | 现在 | 改成 |
|---|---|---|
| 首页 | 开单：分类 + 商品 + 购物车 + 结算 | 记账：本场概览 + 流水 + 记一笔 |
| 单据 | 购物车 → 收款 Sheet → 找零 → 完成 | 记一笔：商品行 + 成交金额 + 赠品 + 支付方式 → 保存 |
| 报表 | 按自然日 / 日期选择 | 按场次；收摊结账截止 |
| 支付 | 收款时选，现金有找零 | 单据上记录"这单怎么收的钱"，无找零 |
| 库存 | 实时超卖提示 | 账面估算；只提示"可能漏记进货" |
| 数据 | orders / lines / batches / adjustments | 新增 sessions；orders 挂 sessionId；lines 加 gift |

### 0.3 建议实施顺序（不要跳）

```
阶段 0  数据层：types → db(v3) → repo(session/saveRecord) → calc(sessionReport) → 单测
阶段 1  记账：RecordPage + RecordEditor + ProductPicker + 保存/撤销
阶段 2  结账：CloseSessionSheet + session 状态 + 报表按场次
阶段 3  辅页：历史/库存/进货/商品/设置适配
阶段 4  同步/合并/迁移 + E2E + 无障碍回归
```

**不要先删 `SellPage.tsx`**。先新建 `RecordPage` 并切换入口，旧页面保留一个版本，确认数据迁移和同步都正常后再删。

## 1. 数据层改动

### 1.1 `src/db/types.ts`

**新增 Session**

```ts
export interface Session {
  id: string;
  deviceId: string;
  /** 第一笔记账时间，ISO */
  startedAt: string;
  /** 结账时间；空 = 进行中 */
  closedAt?: string;
  status: 'open' | 'closed';
  openedBy: string;
  closedBy?: string;
  /** 结账后补记的单数 */
  patchedCount: number;
  /** 结账汇总快照，可选；用于避免历史被后续补录影响 */
  summary?: SessionSummary;
  /** 合并冲突用 */
  updatedAt: string;
  note?: string;
}

export interface SessionSummary {
  orderCount: number;
  lineCount: number;
  revenueFen: number;
  cashFen: number;
  wechatFen: number;
  alipayFen: number;
  costFen: number;
  grossFen: number;
  discountFen: number;
  giftCostFen: number;
  giftQty: number;
}
```

**改 SalesOrder**

- 新增 `sessionId: string`（必填；迁移前的旧数据允许 `undefined`，由迁移函数补齐）。
- `voided` 保留，用于兼容旧数据和历史修正；新流程优先"删除进行中的单"，不再把作废作为主操作。

**改 SaleLine**

- 新增 `gift?: boolean`。
- 赠品行约定：`unitPriceFen=0`、`amountFen=0`、`discountFen=0`；成本仍由 FIFO 计算。
- **重要**：现有 `checkout` 用 `max(0, (listUnitPriceFen - unitPriceFen) * qtyBase)` 算让利。赠品若沿用这条会把整份标价算成"让利"，必须显式置 0，或在 calc 中排除 `gift`。

**改 AppData / EMPTY_DATA**

- 增加 `sessions: Session[]`。
- `loadAll`、备份、合并、清空都要同步。

**改 SETTING_KEYS（可选）**

- 不需要存 `currentSessionId`；用 `sessions` 里 `status='open'` 查询。若担心索引，可加 `SETTING_KEYS.openSessionId` 作为缓存，但必须与 sessions 一致，不建议。

### 1.2 `src/db/db.ts`

新增 version 3：

```ts
this.version(3).stores({
  sessions: 'id, status, startedAt, closedAt, deviceId',
  orders: 'id, createdAt, deviceId, payMethod, voided, sessionId'
});
```

注意：

- Dexie 升级只加表/索引，不会自动改已有记录；`sessionId` 由迁移函数补。
- `OutboxRow.kind` 增加 `'session'`（见 1.6）。
- 不要在 version 3 里改 `lines` 的索引（`gift` 不需要索引）。

### 1.3 `src/db/repo.ts`

**新增函数（建议命名）**

| 函数 | 作用 | 关键规则 |
|---|---|---|
| `getOpenSession(deviceId)` | 查本机 open 场次 | 没有返回 undefined |
| `ensureOpenSession(deviceId, operator)` | 没有就创建 | 第一笔记账时调用；`startedAt=nowIso()`、`status='open'`、`patchedCount=0` |
| `saveRecord(input)` | 保存一单（order + lines） | 事务内写两表；自动 `ensureOpenSession`；写 outbox |
| `updateRecord(id, input)` | 编辑进行中的单 | 仅 `session.status='open'` 允许；改 lines 用"删旧建新"或逐行更新 |
| `deleteRecord(id)` | 删除进行中的单 | 仅 open；同步删 lines；写 outbox delete |
| `closeSession(sessionId, operator)` | 收摊结账 | 计算 summary → 写 `closedAt/status/closedBy/summary`；不删任何单 |
| `reopenSession(sessionId)` | 撤销结账 | 仅下一场未开始；清 `closedAt`、status=open |
| `addPatchedRecord(input)` | 补记到已结账场次 | 写 order + lines，`session.patchedCount += 1`，更新 `summary`（重算） |
| `migrateSessions()` | 历史数据迁移 | 见第 5 节 |

**`saveRecord` 输入契约**

```ts
interface RecordInput {
  deviceId: string;
  operator: string;
  payMethod: PayMethod;
  sessionId?: string;        // 补记时传；正常记账不传
  note?: string;
  lines: {
    productId: string;
    qtyBase: number;
    unit: 'box' | 'base';
    qty: number;
    listUnitPriceFen: number;
    unitPriceFen: number;     // 赠品为 0
    amountFen: number;        // 用户填的成交金额（行）
    gift?: boolean;
  }[];
}
```

**校验（repo 层兜底，不只靠 UI）**

- 至少 1 行。
- `qtyBase > 0`。
- `amountFen >= 0`；`gift` 行强制 0。
- `sessionId` 存在时必须是 closed 且属于本机/可补记。
- `unitPriceFen = round(amountFen / qtyBase)`（展示用；赠品 0）。
- `listAmount = listUnitPriceFen × qtyBase`。
- `totalFen = Σ amountFen`（不是 `qty × unitPrice`，以用户填的成交额为准）；保存前校验 `totalFen` 与 lines 之和一致。
- `discountFen = gift ? 0 : max(0, listAmount − amountFen)`。

**保留/调整旧函数**

- `checkout()`：可保留为内部实现，但新 UI 不再调用；建议改名为 `createRecord` 并删除 `CartLineInput` 语义。
- `voidOrder()/restoreOrder()`：保留给历史数据与"已结账场的修正"；新 UI 的删除走 `deleteRecord`。
- `clearAllData()`：增加 `db.sessions.clear()`。
- `loadAll()`：增加 `sessions`。

### 1.4 `src/db/calc.ts`

**新增**

```ts
export function sessionReport(
  sessionId: string,
  orders: SalesOrder[],
  lines: SaleLine[],
  fifo: FifoResult
): SessionSummary
```

规则：

- 只统计 `order.sessionId === sessionId && !order.voided`。
- 收款按 `payMethod` 汇总。
- `revenueFen = Σ order.totalFen`（应等于 lines 的 amountFen 之和）。
- `costFen = Σ fifo.lineCost`（含赠品行）。
- `grossFen = revenue − cost`。
- `discountFen = Σ line.discountFen`（赠品已为 0）。
- `giftCostFen = Σ gift 行的 fifo.lineCost`。
- `giftQty = Σ gift 行的 qtyBase`。

**改 `productMargins`**

- 增加按 `sessionId` 过滤的重载/新函数 `productMarginsBySession`。
- 返回增加 `giftQty`、`giftCostFen`、`discountFen`（已有 discountFen）。
- 排序：毛利降序；成本缺失（`fifo.lineCost` 未覆盖）排最后。

**保留 `dayReport` / `rangeReport`**

- 旧历史数据迁移后仍可用；但新 UI 不再按日查询。保留至少一个版本，避免旧备份/旧页面崩溃。

**成本缺失**

- 现有 `uncoveredQty` 是全局的；场次报表需要按场次统计"未覆盖件数"。可在 `sessionReport` 里累加赠品/普通行的未覆盖成本，或在 UI 显示全局提示 + 场次毛利"—"。

### 1.5 `src/db/merge.ts`

- `BackupFile.version` 升到 `2`，`data` 增加 `sessions`。
- `parseBackup` 兼容 version 1：`sessions: d.sessions ?? []`。
- `importMerge`：
  - sessions 按 id 并集；同 id 取 `updatedAt` 新者。
  - **closed 优先**：一边 open、一边 closed 时，closed 胜（避免合并后把已结账场次拉回 open）。
  - 补记计数取 `max`，不累加（同一补记单会被 UUID 去重）。
- `replaceAll`：加 `db.sessions.clear()` 与 `bulkPut(d.sessions ?? [])`。
- 备份预览（SettingsPage）增加 sessions 条数。
- 旧版本备份导入后，启动迁移函数补齐 sessionId。

### 1.6 同步（`outbox.ts` / `sync.ts` / `db.ts`）

- `OutboxRow.kind` 与 `SyncKind` 增加 `'session'`。
- `enqueueAllLocal` 增加 sessions。
- `sync.ts`：
  - `Kind` 加 `'session'`。
  - `getLocal` / `deleteLocal` 加 `db.sessions`。
  - `applyRemote` 加 `case 'session'`：按 `updatedAt` 新者胜；`closed` 优先于 `open`。
  - 云端表 `yh_records` 不用改结构（kind 是文本）。
- 同步顺序不要求（Supabase 一次 upsert 全量）；拉取时 order 可能先于 session 到达，报表按 `sessionId` 分组，session 后到会自动补上。
- 旧客户端（未升级）拉到 `session` kind 会走 default 分支吗？需要确认 `applyRemote` 的 switch 是否有 default；建议旧客户端至少忽略未知 kind，不崩。发布顺序：先发客户端（兼容 session），再让用户升级；或服务端无感。

### 1.7 迁移（`migrateSessions`）

**触发时机**

- App 启动、`loadAll` 之前（`ready` 之前）。
- 只在检测到"存在 `sessionId` 为空的订单"时执行。
- 迁移完成写一个 setting `sessionsMigrated='1'`，避免重复。

**聚合规则（建议）**

1. 取出所有 `sessionId` 为空的订单，按 `createdAt` 升序。
2. 按**本地自然日**分组；同一天内若相邻两单间隔 > 4 小时，切分为不同场次（摊位通常中间有休息）。
3. 每个分组创建一条 `Session`：
   - `id = uuid()`
   - `startedAt = 第一单 createdAt`
   - `closedAt = 最后一单 createdAt`（视为已结账）
   - `status='closed'`
   - `deviceId = 该组订单的 deviceId`（混合来源时取第一单）
   - `patchedCount=0`
   - `summary` 用迁移后的数据计算
4. 批量写回 `orders.sessionId`。
5. 生成一条 `sessions` 记录并 enqueue。

**验收**

- 迁移前后：订单总数、销售额、现金/微信/支付宝、毛利完全一致。
- 重复执行不产生新场次。
- 迁移失败时回滚事务，App 仍能打开（显示错误 + 重试）。

## 3. 关键流程时序

### 3.1 保存一单

```
用户点"保存并下一单"
  → UI 校验（至少 1 行、数量>0、金额≥0、0 元需赠品确认）
  → repo.saveRecord()
      → 事务：ensureOpenSession → put order + bulkPut lines
      → enqueue('order', id) + enqueue('line', ...) +（新场次时）enqueue('session')
  → 成功：Toast「已记 1 单 ¥95 · 撤销」
  → 清空草稿；本场计数 +1；焦点回"添加商品"
  → 失败：保留草稿；error Toast；按钮恢复
```

### 3.2 收摊结账

```
点"收摊结账"
  → 读取本场 orders/lines → sessionReport()
  → 打开 CloseSessionSheet（预览 + 检查项）
  → 用户确认
  → repo.closeSession()
      → 重算 summary
      → 事务：更新 session（closedAt/status/summary）
      → enqueue('session')
  → 结果页：查看报表 / 撤销结账
  → 回到记账页：新的一场
```

### 3.3 补记到上一场

```
报表 → 历史场次 → "补记到这一场"
  → RecordEditor（sessionId 固定）
  → repo.addPatchedRecord()
      → 写 order + lines
      → session.patchedCount += 1
      → 重算 summary
      → enqueue('session') + order/line
  → 报表标"补过 N 单"；金额重算
  → 若该场已导出/已对账，结果页提示"这场已对过账，补记后请重新核对"
```

### 3.4 撤销结账

```
结果页"撤销结账" → ConfirmSheet
  → repo.reopenSession()
      → 校验：该场之后没有新场次（或允许？按已定：下一场开始前）
      → 清 closedAt / status=open / 保留 summary? 清空 summary 或保留待重算
      → enqueue('session')
  → Toast「已恢复本场」
```

## 4. 组件级契约（给开发对齐）

| 组件/函数 | 输入 | 输出 | 失败 |

## 5. 迁移与兼容

### 5.1 历史数据

- 已上线数据没有 `sessions` / `sessionId` / `gift`。
- 迁移函数按 1.7 执行；`gift` 默认 `false`。
- 旧 `discountFen` 保留原值；新逻辑只对新增单生效。

### 5.2 备份

- `BackupFile.version` 1 → 2；导入 v1 时 `sessions=[]`，启动后迁移。
- 导出文件名不变；内容多 `sessions`。
- 合并预览显示 sessions 条数，避免用户不知道多了什么。

### 5.3 云端

- `yh_records` 无需改表；新增 kind `'session'`。
- 旧客户端遇到未知 kind：确认 `applyRemote` 的 switch 有默认分支（忽略），否则需要先发兼容版本。
- 云端已有旧订单：拉取后 `sessionId` 为空，迁移函数补齐。

### 5.4 回滚

- 数据库 version 3 不可自动降级；回滚需保留 v1 备份。
- 上线前要求：**先导出一次当前账本**，并保留 `SellPage` 一个版本，便于紧急回退。
