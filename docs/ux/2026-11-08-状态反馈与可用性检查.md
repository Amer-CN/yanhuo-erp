## 7. 状态反馈体系

### 7.1 反馈层级

| 层级 | 用在哪 | 组件 | 阻塞 | 例子 |
|---|---|---|---|---|
| 强反馈 | 截止/不可逆/大范围影响 | Sheet / 页面 | 是 | 收摊结账、撤销结账、清空数据、合并 |
| 中反馈 | 已生效、可反悔 | Toast（可带撤销） | 否 | 已记 1 单、已进货、已修正库存、已结账 |
| 弱反馈 | 连续操作 | 角标 / 行内文字 / 微动效 | 否 | 本场单数 +1、金额变化、让利实时、同步状态点 |
| 静默 | 无需知道 | 无 | 否 | 切分类、搜索、滚动 |

**规则**

1. 能撤销的不用强反馈；只有"截止"和"不可逆"才用 Sheet。
2. 一次操作只给一个主反馈，不叠加。
3. 金额类反馈必须带数字（"已记 1 单 ¥95"），不写"保存成功"。
4. 结账是截止动作，必须强反馈；保存单据是中反馈。

### 7.2 六态总表

#### 记账首页

| 状态 | 触发 | 用户看到 | 可做 |
|---|---|---|---|
| 默认 | 本场进行中 | 本场起止、单数、销售额、流水、记一笔 | 记一笔/结账/看单 |
| 加载 | 首次打开 | "正在打开账本…" | 等待；>3s 提示"打开较慢" |
| 成功 | 保存单据后 | 本场单数/金额 +1；流水新增；Toast | 继续记/撤销 |
| 错误 | 保存失败 | error Toast；单据保留 | 重试 |
| 空态 | 本场 0 单 | "这一场还没记单" + 记一笔 | 记一笔 |
| 禁用 | 本场 0 单 | 收摊结账禁用 + "还没记单" | 记一笔 |
| 条件态 | 跨天未结账 | 顶部提示"昨天那场还没结账" | 去结账/继续记 |

#### 单据编辑（记一笔）

| 状态 | 用户看到 | 可做 |

| 空态 | 没有商品行："还没加商品" + 添加商品 | 加商品 |
| 禁用 | 保存中；金额非法/无商品 | 补全 |
| 草稿 | 离开后回来 | "继续上次没记完的单？"（P1） | 继续/丢弃 |

| 错误 | 结账失败：Sheet 保留，error Toast | 重试 |

| 状态 | 用户看到 | 可做 |

| 页面 | 默认 | 空态 | 错误 | 加载 |
|---|---|---|---|---|
| 进货 | 表单 + 今天已录 | 无商品 [新建]；今天没录 | 校验就地；失败保留 | 保存中 |
| 库存 | 有货/缺货种数、成本、列表 | 无商品 [去建]；无批次 [去进货] | 调整失败保留 | 本地即时 |
| 设置 | 字段、同步、备份 | 还没导出/同步 | 人话错误 + 重试 | 同步中/合并中 |

### 7.3 场次状态机

| 状态 | 判定 | 文案 | 动作 |
|---|---|---|---|
| 无场次 | 首次使用 / 清空后 | "还没开张，记一笔就开始这一场" | 记一笔（自动开场） |
| 进行中（open） | 有 open session | "本场 · 18:20 开始 · 已记 5 单" | 记一笔 / 收摊结账 |
| 跨天未结 | open 且开始日期 < 今天 | "昨天那场还没结账" | 去结账 / 继续记 |
| 已结账（closed） | closedAt 非空 | "11-08 场已结账" | 看报表 / 补记（标补过） |
| 补过 | patchedCount > 0 | "补过 N 单" | 看补过的单 |
| 已撤销结账 | 从 closed 回到 open | "已恢复本场" | 继续记 / 再结账 |

**规则**

- 场次由"第一笔记账"自动创建，不提供"开始营业"按钮。
- 结账是唯一截止动作；结账后下一笔记账自动开新场。
- 跨天不自动结账，只提醒；用户不处理就继续并入旧场（必须在界面明示）。
- 结账撤销只允许在下一场开始前；下一场已开始则不再提供撤销（改为补记（标补过））。

### 7.4 云同步状态机

| 状态 | 判定 | 文案 | 动作 |
|---|---|---|---|
| 未配置 | 无 config | "未开启（点设置与同步）" | 去设置 |
| 离线 | `!navigator.onLine` | "离线，照常记账；联网自动补发" | 无 |
| 同步中 | syncing | "同步中…" | 等待 |
| 待推送 | pending>0 在线 | "已连接 · 待推送 N 条" | 立即同步 |
| 已连接 | pending=0 无错 | "已连接 · 已同步" | 立即同步 |
| 出错 | error | "连不上云端，可能是网络或项目暂停" | 重试/详情 |
| 恢复 | 回到已连接 | Toast「已恢复同步，补发 N 条」 | 无 |

- 同步永远不阻塞记账与结账；结账前只提示"还有 N 条没同步"，不强制。
- 两台设备各自记账时，本场是**本机场次**；云同步/合并后报表按记录汇总（默认各设备场次并列，报表按记录汇总）。

### 7.5 Toast 规范

| 语气 | 时长 | 关闭 | 动作 | ARIA |
|---|---|---|---|---|
| success | 2600ms | 无 | 可带撤销 | status/polite |
| warning | 4000ms | 无 | 可带撤销 | status/polite |
| error | 5200ms | 有 | 可带重试 | alert/assertive |
| 带动作 | 6000ms 或手动 | 有 | ≥44px | 同语气 |

**规则**

1. 同一时间一条，新消息替换并重置计时。
2. 带"撤销"的 Toast：悬停/键盘聚焦暂停计时；移动端建议 8 秒或提供关闭（WCAG 2.2.1）。
3. 文案 = 动作 + 对象 + 金额；例："已记 1 单 ¥95"、"已结账 · 12 单 ¥1,280"。
4. 不用"操作成功""保存成功"。
5. 错误必须含"怎么办"（见 7.7）。

### 7.6 撤销矩阵

| 操作 | 可逆 | 方式 | 窗口 | 撤销后 |
|---|---|---|---|---|
| 保存单据 | 可逆 | Toast 撤销 | 6s | 删除该单，本场计数回退 |
| 编辑单据 | 可逆 | Toast 撤销 | 6s | 恢复编辑前 |
| 删除单据 | 可逆 | Toast 撤销 | 6s | 恢复整单 |
| 收摊结账 | 可逆 | 结果页「撤销结账」 | 下一场开始前 | 场次回到 open |
| 补记到上一场 | 可逆（补过） | 删除补记单 | 6s / 场次详情 | 补过单数回退，报表重算 |
| 进货保存 | 可逆 | Toast 撤销 | 6s | 删除批次 |
| 删除进货 | 可逆 | Toast 撤销 | 6s | 恢复批次 |
| 修正库存 | 可逆 | Toast 撤销 | 6s | 反向调整 |
| 停用商品 | 可逆 | Toast 撤销 | 6s | 重新启用 |
| 合并 | 可逆 | 结果页撤销 | 关闭前 | 恢复合并前快照 |
| 清空数据 | 不可逆 | 专用 Sheet + 输入确认 | — | 导入备份 |
| 关闭云同步 | 可逆（重配） | Sheet 确认 | — | 重新开启 |

**规则**

- 撤销必须幂等；撤销后给"已撤销"反馈。
- 结账撤销是高风险动作：结果页按钮 + 确认 Sheet（"撤销后本场恢复进行中，可继续记"）。
- 超过窗口的恢复走业务入口：已结账场次 → 补记/补过；历史 → 查看。

### 7.7 错误文案三段式

| 场景 | 文案 |
|---|---|
| 保存单据失败 | "这单没记上，可能是手机存储满了。内容还留着，清点空间后再点保存。" |
| 未加商品 | "先加一个商品，再保存这一单。" |
| 数量为 0 | "数量要大于 0；按箱记就填箱数。" |
| 金额非法 | "成交金额填个数字，比如 95 或 95.5。" |
| 金额为 0 | "这单是 0 元。如果是赠品，打开赠品开关；不是的话检查金额。" |
| 结账失败 | "结账没完成，本场还在。再点一次确认；数据不会丢。" |
| 撤销结账失败 | "没恢复成功，本场仍是已结账。再试一次，或去看报表。" |
| 补记失败 | "补记没保存，这一场还是原来的数。内容还留着，再点保存。" |
| 跨天未结账 | "昨天那场还没结账。先结账，今天的单才会算到今天。" |
| 同步失败 | "连不上云端，可能是网络或项目暂停。记账不受影响，联网会自动补发。" |
| 导入文件损坏 | "这个文件不是烟花账备份，或内容坏了。换一个最近导出的 .json。" |
| 合并失败 | "合并没完成，账本没变。先导出本机备份，再试一次。" |
| 备份失败 | "导不出来，可能浏览器不允许下载。试试系统分享，或换 Chrome/Safari。" |
| 账本打不开 | "账本打不开，可能存储不足或浏览器清了数据。先刷新；还不行就导入最近备份。" |

**禁止**：直接展示 `QuotaExceededError`、`fetch failed`、`401`；禁止指责性文案。

### 7.8 加载预算

| 时长 | 处理 | 例子 |
|---|---|---|
| 0–100ms | 无 loading | 加商品、改数量/金额、本场计数 |
| 100–300ms | 微反馈 | 打开 Sheet、选商品 |
| 300ms–1s | 按钮 loading | 保存单据、保存进货 |
| 1–10s | 按钮 loading + 说明 | 结账、同步、合并 |
| >10s | 后台执行 + "会自动重试" | 云同步 |

- 本地写入 <100ms，不显示骨架屏。
- 结账通常 <1s（本地聚合）；数据量大时按钮 loading，不关遮罩。
- 同步永不阻塞。

| 金额修改 | 数字变化 | 即时 | 让利实时 |

## 8. 防错与边界条件

### 8.1 漏记（最大的风险）

| 环节 | 设计 |
|---|---|
| 结账前 | 预览显示"本场 N 单 · ¥X"，并问"还有没记的单？" + [再记一笔] |
| 跨天 | 打开记账页提示"昨天那场还没结账"；不自动结账 |
| 收摊后想起 | 允许"补记到上一场"，标"补过"（已定） |
| 备份 | 结账结果页"导出备份"；更多页体检"N 天没备份" |
| 草稿 | 单据中途离开自动存草稿（P1），回来提示继续 |

### 8.2 记重（同一单记两遍）

| 环节 | 设计 |
|---|---|
| 保存后 10 秒内 | 若金额、商品、支付方式完全相同 → warning"可能重复记了，确认？"（不阻止） |
| 流水 | 同一时间段的单可见；删除/撤销 |
| 结账前 | 单数/金额异常增长不提示（避免误报） |
| 报表 | 不自动去重（UUID 不同就是两单） |

### 8.3 记错（商品/数量/金额/支付方式）

| 场景 | 处理 |
|---|---|
| 进行中场次 | 点单 → 编辑；保存后 Toast 撤销；删除可撤销 |
| 已结账场次 | 不允许直接改；走"补记到这一场"新增一单，或"撤销结账"后改（窗口内） |
| 支付方式错 | 进行中可直接编辑；已结账走补过 |
| 商品选错 | 删除行/换商品；已保存的整单删除重记 |
| 金额多按一个 0 | 编辑金额；结账前复核合计 |

### 8.4 金额与让利口径

| 概念 | 定义 | 展示 |
|---|---|---|
| 标价金额 | `priceList × qtyBase`（按行） | 行内灰字"标价 ¥50" |
| 成交金额 | 用户输入的实际收款（按行） | 行内主数字 |
| 让利 | `max(0, 标价 − 成交)`，按行求和 | 行内/合计"让利 ¥5" |
| 高于标价 | 成交 > 标价 | 提示"高于标价 ¥X"，让利记 0 |
| 赠品 | 开关打开，成交 0 | "赠品 · 成本 ¥8" |
| 赠品成本 | 赠品行 FIFO 成本 | 合计"赠品成本 ¥X" |
| 毛利 | 销售额 − 全部成本（含赠品） | 报表主数字 |
| 销售额 | 各行成交金额之和（赠品 0） | 报表主数字 |

**规则**：赠品不混入"砍价让利"，单独统计"赠品成本"，避免口径打架。

### 8.5 场次边界

| 场景 | 规则 |
|---|---|
| 首次记账 | 自动创建 open 场次，无需"出摊" |
| 结账 | closed；记录 closedAt；本场只读 |
| 下一笔记账 | 自动创建新场 |
| 跨天未结账 | 只提醒；继续记账并入旧场（界面明示"仍算昨天那场"） |
| 结账后补记 | 走"补记到上一场"，标"已补过"；报表重算 |
| 撤销结账 | 下一场开始前可用；恢复 open |
| 下一场已开始 | 不再允许撤销上一场；只能补记（标补过） |
| 两台设备 | 各自场次独立；合并后报表按记录汇总（默认各设备场次并列） |

### 8.6 库存口径

| 场景 | 设计 |
|---|---|
| 记账加商品 | 库存 ≤0 仍可加；行内黄字"账面 0/负，可能漏记进货" |
| 保存单据 | 不阻止；库存扣减（FIFO） |
| 库存页 | "账面没货/账面为负"，不写"超卖"（事后记账没有实时超卖） |
| 负库存 | 排序靠前；详情给 [去补录进货] [修正库存] |
| 报表 | 负库存不影响销售额；毛利可能因缺批次显示"—" |
| 体检 | "账面没货 N 种"计入 |

### 8.7 支付方式与现金对账

| 场景 | 设计 |
|---|---|
| 一单一方式 | 现金/微信/支付宝单选；默认上次 |
| 混合支付 | 已定一单只记一种；遇到混合就拆成两单，或在备注写"微信 50 + 现金 50" |
| 现金对账 | 报表"现金"= 本场现金单成交额合计；没有"实收/找零"概念 |
| 合计校验 | 现金+微信+支付宝 必须等于销售额；不一致红色提示 |
| 支付方式错 | 进行中可编辑；已结账走补过 |

### 8.8 两台设备与合并

| 用户疑问 | 界面回答 |
|---|---|
| 这是同一本账吗 | 设备名 + 同步码后 4 位 + 上次同步时间 |
| 对方记的我能看到吗 | "已连接 · 已同步"；列表自动更新 |
| 本场是两台一起的吗 | 本场是本机的；报表合并后按记录汇总（需明确文案） |
| 待推送是什么 | "还没传上去的 N 条，联网自动补发，不影响记账" |
| 合并会重复吗 | "同一条记录只算一次" |
| 场次会合并吗 | 默认各设备场次并列；报表按记录汇总 |

### 8.9 数据丢失与备份

| 风险 | 设计 |
|---|---|
| iOS 清缓存 | 设置页说明 + 每天收摊备份提醒 |
| 忘记备份 | 更多页体检"已 N 天没备份"；结账结果页 [导出备份] |
| 导出失败 | 人话 + 系统分享回退 |
| 换机 | 导出 → 新机安装 → 导入 → 核对商品数/本场销售额/负库存 → 改设备名 |
| 清空 | 专用 Sheet + 输入"清空" + 复选框（云端/已备份） |

## 10. 验收标准

### 10.1 P0 项

| 项 | 通过标准 |
|---|---|
| 记一笔 | 选商品→数量→金额→保存 ≤40s；保存后本场单数/金额 +1；Toast 可撤销 |
| 连续补记 | "保存并记下一单"后表单清空、支付方式保留、焦点回商品；不回列表 |
| 整单金额 | 默认标价合计；改为 95 后让利 = 标价−95；0 元提示赠品 |
| 赠品 | 开关后金额 0；显示成本；报表赠品成本正确；毛利含赠品成本 |
| 场次 | 首次记账自动 open；结账后 closed；下一笔记账新场 |
| 收摊结账 | 预览数据正确；确认后本场只读；结果页可查看报表 |
| 撤销结账 | 下一场开始前可撤销，本场回到 open |
| 撤销单据 | 保存/删除后 6s 可撤销，本场计数回退 |
| 库存口径 | 文案"账面没货/账面为负"，不阻止记账 |
| 支付方式 | 默认上次；保存后报表按方式汇总；合计校验通过 |

## 11. 优先级

### P0（模型重构，必须）

1. 记账首页（本场概览 + 流水 + 记一笔）。
2. 单据编辑（商品行、数量、整单金额、赠品、支付方式、保存并下一单）。
3. 选商品 Sheet（点选加入、保持打开、已加角标）。
4. 场次数据层（sessions + orders.sessionId）与收摊结账。
5. 撤销单据/删除单据。
6. 报表按场次统计；合计校验。
7. 库存文案口径（账面）。

### P1

- 撤销结账；补记上一场 + 补过徽标。
- 草稿恢复；复制上一单。
- 报表"让利/赠品"列；历史按场次。
- 账本体检；跨天未结账提醒。
- 进货连续录入规则修正；单位换算。
- 设置字段保存反馈；人话错误。

### P2

- 按单价输入；混合支付拆分。
- 库存变动时间线；商品置顶。
- 新版本提示；桌面双栏。

### 不建议

- 购物车、结算、收款完成、找零等实时收银流程。
- "开始营业/出摊"按钮。
- 按自然日切报表。
- 在记账路径上弹多步引导。
