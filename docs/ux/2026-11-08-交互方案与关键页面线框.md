## 0. 先纠正产品形态

这不是收银台，是**两个人自己用的台账本**。

| 错误假设（v1） | 真实情况（v2） | 交互后果 |
|---|---|---|
| 顾客在摊前，摊主实时点商品、加购物车、结算 | 交易发生时**完全不操作 App**；顾客走了、空闲了再补记 | 删除购物车、结算、收款完成、找零整套流程 |
| 一单一单地实时收银 | 一次空闲可能补记 5–6 单、对应 8 个客人 | 支持**连续补记**，保存后立刻准备下一单 |
| 收摊按自然日切分报表 | 营业时间不固定，**点「收摊结账」即截止**，下一单自动算下一场 | 用「场次（账期）」代替日期选择器 |
| 库存不足要阻止或二次确认 | 库存只是账面估算，卖超通常意味着漏记进货 | 只提示"可能漏记进货"，不阻止 |
| 需要"出摊"按钮开始营业 | 不需要。第一笔记账自动开场，收摊点一次结账 | 只保留「收摊结账」一个截止动作 |

**一句话**：App 只做三件事——把刚才卖的东西记下来、把账算清、收摊时截住这一场。

## 1. 场景与设计目标

### 1.1 真实使用节奏

```
顾客来 → 正常交易（不看手机） → 顾客走
   → 摊位空闲（3–10 分钟）→ 打开 App 补记刚才几单
   → 继续营业 → …… → 收摊 → 点「收摊结账」→ 看本场报表 → 备份
```

| 约束 | 事实 | 交互后果 |
|---|---|---|
| 记录时机 | 事后回忆，不是实时 | 界面要能快速连续录入；允许改金额；允许标记赠品 |
| 记忆负担 | 一次补记多单，容易记混 | 保存后显示"本场已记 N 单"；支持复制上一单；流水可回看 |
| 手 | 可能戴手套、单手 | 主操作 ≥56px；数量步进器；金额用数字键盘 |
| 环境 | 夜间、低温、强光/弱光 | 暗色默认；金额最高层级；不靠颜色单独传意 |
| 网络 | 断网常态 | 先本地保存；同步只告知；结账不依赖网络 |
| 精度 | 事后可能只记得"这单收了 100" | 金额默认按整行成交额输入，不强迫记单价 |
| 两人 | 两台手机、各自记账 | 操作人按设备记住；场次按设备独立，靠云同步/合并汇总 |

### 1.2 设计目标（可验证）

| 目标 | 指标 | 目标值 |
|---|---|---|
| 补记要快 | 记一单（2–3 个商品）的中位时长 | ≤ 40 秒 |
| 连续补记不中断 | 保存后开始下一单的间隔 | ≤ 3 秒 |
| 算得清 | 每单能看到：成交额、让利、赠品 | 100% 的单据可回溯 |
| 收摊有终点 | 收摊结账完成率 | ≥ 95% 的营业日 |
| 不丢单 | 结账前未保存的草稿 | 0（离开自动存草稿） |
| 错得起 | 可逆操作撤销覆盖率 | ≥ 90% |
| 对得上 | 现金/微信/支付宝合计 = 本场销售额 | 100% |

### 1.3 设计原则（冲突时排序）

1. **事后优先**：所有交互按"回忆并补记"设计，不模拟收银动作。
2. **金额优先**：一单最终要回答"收了多少钱"，金额输入永远在数量之后、最显眼。
3. **连续优先**：保存不是终点，保存后立刻能记下一单。
4. **先本地、后云端**：断网不影响记账与结账。
5. **可撤销 > 二次确认**：记错单、结错账都要能反悔；只有清空数据不可逆。
6. **场次是边界**：结账即截止；截止后的补记必须显式标"补过"，不能偷偷改历史。

## 2. 用户旅程地图

### 2.1 全景（一个营业日）

| 阶段 | 触点 | 用户意图 | 情绪 | 痛点 | 设计机会 |
|---|---|---|---|---|---|
| 出摊 | 打开 PWA | 确认昨晚已结账、货够 | 赶时间 | 昨天忘了结账；不知道哪些货快没了 | 跨天未结账提醒；账本体检 |
| 营业中 | 不看 App | 正常卖货 | 忙 | — | 不打扰 |
| 空闲补记 | 记账页 → 记一笔 | 把刚才 5–6 单快速记下 | 怕记混、怕算错 | 记不清单价；忘了谁付的现金；赠品没地方记 | 连续补记；整单金额；赠品开关；复制上一单 |
| 补记中的犹豫 | 单据编辑 | 这单是 100 还是 95？送了一挂？ | 不确定 | 没有"大概"的输入方式；改来改去 | 金额可改；让利自动算；赠品单独标 |
| 继续营业 | 返回记账页 | 看本场进度 | 安心 | 不知道今天记了几单、收了多少钱 | 本场概览：起始时间、单数、销售额 |
| 收摊 | 收摊结账 | 截止本场、对现金、看毛利 | 疲惫 | 怕漏记；怕现金对不上；怕没同步 | 结账预览 + 异常检查 + 确认 |
| 结账后 | 报表 / 历史 | 看这一场卖了多少、哪个货让利最多 | 想快点回家 | 报表按日期切分不符合"这一场" | 本场报表；历史场次；让利/赠品列 |
| 异常 | 记账 / 报表 / 更多 | 漏记、记重、跨天没结账 | 焦虑 | 不知道该改哪 | 撤销；补记上一场；账本体检 |

### 2.2 情绪曲线

```
情绪
 高 |                         ●记完一场              ●对平
    |              ●记一笔
 中 | ●出摊   ●营业中              ●结账
    |                                      ●漏记/记重
 低 |                                                ●现金对不上
    +------------------------------------------------→ 时间
      出摊   营业   空闲补记   继续营业   收摊   结账后
```

- **低谷 1（补记时记不清）**：用"整单成交额"降低回忆精度要求；赠品用开关，不强迫记单价。
- **低谷 2（收摊怕漏）**：结账预览先列"本场 N 单、合计 ¥X"，再问"还有没记的吗"。
- **低谷 3（现金对不上）**：不先讲原因，先给三个出口：看现金单、补记、检查作废。

### 2.3 主流程与异常分支

| 流程 | Happy path | 异常分支 | 恢复 |
|---|---|---|---|
| 补记一单 | 记一笔 → 选商品 → 数量/金额 → 支付方式 → 保存 | 记错商品/金额/支付方式/重复记 | 撤销；编辑该单；删除 |
| 连续补记 | 保存并记下一单 → 重复 | 中途被打断 | 草稿自动保存；回来继续 |
| 收摊结账 | 收摊结账 → 预览 → 确认 | 还有未记的单 / 未同步 / 成本缺失 / 现金对不上 | 先补记；先同步；去补录；看现金单 |
| 结账后补记 | 报表 → 补记到上一场 | 已开下一场（仍可补记） | 选择场次补记；标"补过" |
| 进货 | 录一条 → 保存并继续 | 选错商品/单价/单位 | 撤销；编辑；删除 |
| 异常 | 跨天未结账 / 负库存 / 同步失败 | — | 提醒 + 一键去处理 |

## 3. 任务流

### 3.1 记一笔（核心，目标 ≤40 秒）

```
[记账页]
   │ 本场：11-08 18:20 开始 · 已记 5 单 ¥480
   ▼
[记一笔]
   │
   ├─ 支付方式：现金 / 微信 / 支付宝（默认上次）
   │
   ├─ [添加商品] ──▶ 选商品 Sheet（分类/搜索）
   │        │              点商品 → 加入本单，Sheet 保持打开
   │        │              已选商品显示"已加 1"
   │        └─ [完成] 返回单据
   │
   ├─ 商品行：名称 · 数量 [−][2][+] · 成交金额 [50.00] · [赠品] · 删除
   │        └─ 自动显示：标价 ¥50 · 让利 ¥5
   │
   ├─ 合计 ¥95 · 让利 ¥5 · 赠品成本 ¥10
   │
   └─ [保存并记下一单]   [只保存]
            │
            ▼
      Toast「已记 1 单 ¥95 · 撤销」
      表单清空，焦点回"添加商品"
```

**为什么是"整单成交额"而不是单价**：事后通常只记得"这单收了 95"。行内金额默认 = 标价 × 数量，用户改成实际收款即可；需要按单价记时，点金额右侧的"按单价"切换。

**决策点**

| 节点 | 用户要决定 | 默认/记忆 | 失败时 |
|---|---|---|---|
| 支付方式 | 现金/微信/支付宝 | 上次使用 | 未选时默认现金？不，保留上次；首次现金 |
| 商品 | 卖了什么 | 最近使用/分类 | 搜索无结果 → 去建商品 |
| 数量 | 几个/几箱 | 1（按上次单位） | 0/负 → 就地提示 |
| 金额 | 这单实际收多少 | 标价合计 | 非数字 → 就地提示；0 元提示"赠品？" |
| 赠品 | 是否白送 | 关 | 开→金额 0，显示成本 |
| 保存 | 继续下一单还是回列表 | 保存并记下一单（高频） | 失败保留输入 |

### 3.2 连续补记（一次 5–6 单）

```
保存第 1 单 → Toast「已记 1 单 · 撤销」
   → 单据清空，本场进度 +1
   → 直接开始第 2 单（不回到列表）
   → ……
   → 记完点"完成"回到记账页
```

**规则**

- 主按钮"保存并记下一单"，次按钮"只保存"（回列表）。
- 保存后保留：支付方式（上次）、操作人、商品分类。
- 保存后清空：商品行、金额、备注。
- 本场进度实时更新："已记 6 单 · ¥560"。
- 支持"复制上一单"：适合连续卖给相似顾客（同款组合），复制后可改数量/金额。
- 草稿：单据编辑中离开（返回/切页/锁屏）自动存草稿；再次进入询问"继续上次没记完的单？"（P1）。

### 3.3 收摊结账（截止本场）

```
[记账页 / 更多页]  [收摊结账]
   │
   ▼
[结账预览 Sheet]
   │ 本场：11-08 18:20 → 11-08 23:40
   │ 已记 12 单 · 销售额 ¥1,280
   │ 现金 ¥800 · 微信 ¥400 · 支付宝 ¥80
   │ 毛利 ¥420 · 让利 ¥60 · 赠品成本 ¥35
   │
   ├─ 检查项：
   │   [ ] 还有没记的单？        → [再记一笔]
   │   [ ] 还有没同步的？        → [立即同步]
   │   [ ] 有成本缺失？          → [去补录]
   │   [ ] 有负库存？            → [去看看]
   │
   └─ [确认收摊结账]
            │
            ▼
      本场归档 → 结果页「已结账 · 查看报表 / 撤销结账」
      下一笔记账自动开新场
```

**规则**

- 收摊结账是**截止动作**，不是"出摊"的反向；没有"开始营业"按钮。
- 首次记账自动创建本场（`session.status=open`），无需手动开场。
- 结账前必须让用户看到"本场有多少单、多少钱"，防止漏记。
- 检查项不阻止结账，只提示；用户可以选择"仍然结账"。
- 结账后结果页给"查看报表"与"撤销结账"（撤销窗口：下一场开始前）。
- 结账时若未同步，提示"先同步再结账，另一台手机才能看到"；不强制。
- 结账后本场只读；补记需走"补记到上一场"，并标"已补过"。

### 3.4 补记到上一场（结账后发现漏记）

```
报表 → 选择场次 → [补记到这一场]
   → 打开单据编辑（场次固定为所选场）
   → 保存 → 该场标记"已补过" → 报表重算
```

**规则**

- 入口只在报表/历史场次详情，不在记账首页（避免日常误用）。
- 补记单据在流水里带"补记"徽标；场次报表顶部显示"本场补过 N 单"。
- 若该场已生成备份/已对账，提示"这场已经对过账，补记后请重新核对"。
- 补记不限时间；每次补记都标"补过"，并重算该场报表。

### 3.5 进货（保留，微调）

```
进货页 → 选商品（可搜索）→ 数量/进价 → 保存并继续
   → Toast「已进货 40 个 · 撤销」→ 表单重置（保留商品/批次/到货日期）
```

- 与记账一致，主按钮"保存并继续"，适合照纸质单连续录。
- 进货不挂在场次上；它影响库存与后续毛利，但不算销售额。
- 单位切换按比例换算（见状态文档 8.2）。

### 3.6 对账（收摊后）

```
本场报表
   ├─ 销售额 = 现金 + 微信 + 支付宝（合计校验）
   ├─ 现金：本场现金单合计（不含找零概念）
   ├─ 毛利 = 销售额 − FIFO 成本（含赠品成本）
   ├─ 让利 = 标价 − 成交（非赠品行）
   ├─ 赠品成本 = 赠品行 FIFO 成本
   ├─ 单品：销量 / 销售额 / 让利 / 赠品 / 毛利
   └─ [复制本场汇总] [导出备份]
```

### 3.7 异常恢复

```
跨天未结账
  ├─ 打开记账页：顶部提示"昨天那场还没结账"
  └─ [去结账] / [继续记]（继续记会并入旧场，需明确提示）

记错单
  ├─ 流水里点该单 → 编辑 / 删除（撤销）
  └─ 已结账场次 → 补记/补过流程

记重单
  ├─ 保存后 10 秒内相同金额/商品 → 提示"可能重复"（不阻止）
  └─ 流水可删除

负库存
  ├─ 记账时行内提示"账面只剩 X，可能漏记进货"
  └─ 不阻止保存；库存页"只看缺货"

同步失败
  ├─ 不影响记账/结账
  └─ 更多页状态 + 待推送条数 + 重试
```

## 4. 信息架构

### 4.1 导航结构（Tab 改名）

```
底部 Tab（5 项）
├─ 记账（默认，原"开单"）
│   ├─ 本场概览 + 流水
│   ├─ 记一笔（单据编辑页/大 Sheet）
│   ├─ 选商品 Sheet
│   ├─ 收摊结账 Sheet → 结果页
│   └─ 历史场次入口（或放报表）
├─ 进货
│   ├─ 录入表单
│   ├─ 今天已录 Sheet
│   └─ 新建商品 Sheet
├─ 库存
│   ├─ 列表 / 搜索 / 只看缺货
│   └─ 商品详情 Sheet（批次 + 修正 + 变动）
├─ 报表
│   ├─ 本场 / 历史场次
│   ├─ 单品（销量/销售额/让利/赠品/毛利）
│   └─ 临期预警
└─ 更多
    ├─ 本场概览 + 收摊结账（也可在记账页）
    ├─ 账本体检
    ├─ 商品管理
    ├─ 销售记录（按场次/单）
    ├─ 设置与同步
    └─ 使用帮助
```

### 4.2 入口优先级

| 优先级 | 入口 | 理由 |
|---|---|---|
| P0 | 记一笔、保存并记下一单 | 每次空闲都用 |
| P0 | 收摊结账 | 每天一次，必须有终点 |
| P1 | 进货、库存 | 每天多次 |
| P1 | 本场报表 | 收摊后 |
| P2 | 商品管理、历史场次、设置 | 每周/一次性 |
| P3 | 使用帮助、安装引导 | 首次/换机 |

**规则**：记账页不出现"购物车""结算""收款"字样；一单的终点是"保存"，不是"收款完成"。

### 4.3 术语替换表

| v1（作废） | v2（统一） |
|---|---|
| 开单 / 购物车 / 结算 / 收款完成 / 找零 | 记账 / 这一单的商品 / 保存 / 已记一单 / 无 |
| 当日 / 全部 | 本场 / 历史场次 |
| 收款方式 | 支付方式（这单怎么收的钱） |
| 改价 | 成交金额 / 让利 |
| 库存不足 | 账面不足（可能漏记进货） |

## 5. 关键页面线框（低保真）

> 线框只表达区域、层级、顺序与状态；`[ ]` 为可点区域，`…` 为滚动内容，`!` 为条件提示。

### 5.1 记账页（首页）

```
┌──────────────────────────────────────────────┐
│ [图标] 记账                        [主题]     │ L0
│ ● 离线，照常记账（轻量状态）                 │ L0 辅助
├──────────────────────────────────────────────┤
│ ! 昨天那场还没结账              [去结账]     │ 条件
├──────────────────────────────────────────────┤
│ 本场 · 11-08 18:20 开始                      │ L1 概览
│ 已记 5 单 · ¥480.00            [收摊结账]    │
│ 现金 ¥300 · 微信 ¥150 · 支付宝 ¥30           │
├──────────────────────────────────────────────┤
│ 本场流水                           [看全部]  │ L2
│ ┌ 21:12 · 我 · 微信        ¥95.00        › ┐│
│ │ 大地红 ×2 · 仙女棒 ×1                     ││
```

### 5.2 记一笔（单据编辑）

```
┌──────────────────────────────────────────────┐
│ [返回] 记一笔                本场第 6 单      │ L0
├──────────────────────────────────────────────┤
│ 支付方式  (现金) (微信) (支付宝)             │ L2 默认上次
│ 操作人    [我 ▾]                             │ L2
├──────────────────────────────────────────────┤
│ 这一单的商品                                 │ L1
│ ┌ 大地红 1000响                        [X] ┐│
│ │ 数量 [−] 2 [+]  成交金额 [50.00]         ││
│ │ 标价 ¥50.00 · 让利 ¥0                    ││
│ │ [ ] 赠品                                 ││
│ ├ 仙女棒                                [X] ┤│
│ │ 数量 [−] 1 [+]  成交金额 [8.00]          ││
│ │ 标价 ¥8.00 · 让利 ¥0                     ││
│ │ [x] 赠品  → 金额 0 · 成本 ¥8.00          ││
│ └───────────────────────────────────────────┘│
│ [＋ 添加商品]                                 │
├──────────────────────────────────────────────┤
│ 合计 ¥50.00   让利 ¥0   赠品成本 ¥8.00      │ L1 金额
│ 备注 [给老顾客搭了一挂…………………]            │ L3
├──────────────────────────────────────────────┤
│ [保存并记下一单]        [只保存]              │ L1 主操作
└──────────────────────────────────────────────┘
```

**规则**

- 商品行顺序 = 添加顺序；不排序、不合并同商品（同商品不同价要分开记）。
- 数量单位：默认上次使用；有箱规时可切"箱"，切换按比例换算。
- 成交金额：默认标价 × 数量；用户直接改总额；右侧"按单价"可切换（P2）。
- 赠品：开关打开后金额变 0，显示"成本 ¥X"（FIFO 成本）；可关闭恢复原金额。
- 合计 = 各行成交金额之和；让利 = 各行 `max(0, 标价−成交)` 之和；赠品成本单独统计。
- 保存校验：至少 1 行；数量 >0；金额 ≥0；金额为 0 且未标赠品 → 提示"0 元，是赠品吗？"。
- 返回：若有未保存内容，Sheet 确认"这单还没保存，离开？"（或自动存草稿，P1）。
- 操作人：默认本机操作人；切换后本单记录该操作人。

## 7. 与现有实现的差距

| # | 现状 | 与 v2 的冲突 | 建议 | 优先级 |
|---|---|---|---|---|
| 1 | 开单页 = 购物车 + 结算 + 收款 | 实时收银模型，不符合事后记账 | **重构为记账首页 + 单据编辑** | P0 |
| 2 | 支付方式在"收款 Sheet"选 | 钱已收，记账时才补 | 移到单据顶部，保存时记录 | P0 |
| 3 | 现金实收/找零 | 事后记账没有找零场景 | 删除现金 Sheet；只记"这单收了多少" | P0 |
| 4 | 报表按自然日 `date` | 营业时间不固定 | 改为按场次（session）统计 | P0 |
| 5 | 无场次概念 | 无法"收摊结账" | 新增 `sessions` + `orders.sessionId` | P0 |
| 6 | SaleLine 无赠品字段 | 赠品无法记录与计成本 | 新增 `gift` 字段；金额 0、成本照算 | P0 |
| 7 | 商品卡只能加购物车 | 需在单据里加行 | 选商品 Sheet 点选加入本单 | P0 |
| 8 | 改价 Sheet（单价语义） | 事后按整单金额更自然 | 行内成交金额，默认整行；单价为进阶 | P0 |
| 9 | 保存后清空购物车、关闭 Sheet | 需连续补记 | "保存并记下一单"，不回列表 | P0 |
| 10 | 无"撤销结账" | 误点结账无法恢复 | 结果页撤销 + 窗口 | P1 |
| 11 | 无"补记上一场" | 结账后漏记无出口 | 报表入口 + 补过徽标 | P1 |
| 12 | 无草稿 | 补记中途被打断会丢 | 单据自动存草稿 | P1 |
| 13 | 历史按日分组 | 应按场次分组 | 销售记录按场次 | P1 |
| 14 | 库存"总件数"跨单位相加 | 语义错误 | 有货/缺货种数 + 成本 | P1 |
| 15 | 进货连续录入清空批号 | 与文案不符 | 保留批次/到货日期 | P1 |
| 16 | 原生 confirm | 与 Sheet 体系不一致 | 统一 Sheet/撤销 | P2 |

**数据层建议（供开发评估）**

- `sessions`：`id, deviceId, startedAt, closedAt?, status('open'|'closed'), openedBy, closedBy, patchedCount（补过单数）, note`。
- `orders` 增加 `sessionId`；结账时写入 `closedAt`。
- `saleLines` 增加 `gift: boolean`。
- 报表按 `sessionId` 聚合；历史场次按 `closedAt` 倒序。
- 结账可存快照（销售额/成本/毛利），补过时重算并更新快照，避免历史受后续补录影响。

## 8. 已确认口径（v2 锁定）

| # | 问题 | 结论 |
